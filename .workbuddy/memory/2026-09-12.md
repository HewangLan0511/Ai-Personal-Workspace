**来源**：项目根目录两份 txt 计划书（`Personal Wrokspace  个人智能工作空间项目设计计划书 V1.0.txt`、`《Personal Workspace 智能工作空间》Agent开发执行计划书 V1.0.txt`）。注意：`docs/` 目录当时是空的。

**产出**：`docs/agent-dev/` 下 14 个 md 文件，共约 2300 行。

**结构**：
- `AGENTS.md` 主入口（十条硬约束 + 五步工作流 + DoD + 汇报格式）
- `01` 项目上下文 / `02` 架构与目录规范 / `03` 数据契约与接口规范（三份长期有效基础文件）
- `04`~`12` 按 MVP→V2→V3 的阶段指令
- `13` 验收清单与禁止事项（红线总表 + MVP 十步验收脚本）
- `README.md` 文件地图与阅读顺序

**关键设计决策（写在指令里，后续开发要遵守）**：
1. 技术栈定为 Tauri 2.x + Vue3 + TS，Rust 做调度核心，Python 做系统调用/AI sidecar。
2. **SQLite 单一写入者 = Rust core**，Python 只能通过 core 的 `/internal/db/*` 接口访问，禁止双写。
3. 工作模式引擎列为全项目最高优先级（★★★★★），阶段顺序调整为 04→05→07→06→08（窗口管理先于模式引擎，因为它是依赖）。
4. 窗口布局用 **0~1 归一化坐标**存储，由 core 换算像素，解决多屏/DPI 问题。
5. 模式应用流程建模为显式状态机（Idle→Validating→Launching→WaitingReady→Arranging→OpeningFiles→LoadingAI→Done），并发启动 + 失败不中断 + 幂等 + 可取消。
6. ADR-001 待定稿：窗口控制与进程启动用 Rust 还是 Python，二选一统一使用（推荐 Rust）。
7. AI Provider 抽象层，业务代码禁止直接发模型 HTTP 请求；API Key 进系统凭据库。
8. 红线：AI 只建议、用户确认（学习进度与个人档案不得由 AI 自动修改）；聊天全文不入库。
9. 插件默认零权限；判定插件架构是否成功的标准 = 新增插件零核心代码改动。

**下一步（未做）**：ADR-001 定稿、脚手架搭建。

## 白宇授权我担任项目监制（审核开发 Agent 的交付）

**新增制度设施**：

| 文件 | 作用 |
|------|------|
| `docs/reviews/SUPERVISOR.md` | 监制章程：角色边界、四条原则、五步审核流程、三档判定、七项送审证据、六维清单、八条红线（V1~V8）、争议处理 |
| `docs/reviews/LEDGER.md` | 审核台账 = **项目进度唯一真相来源**（口头进度与台账冲突以台账为准） |
| `docs/reviews/REVIEW-000-阶段0-基线审核.md` | 首份审核报告（阶段0 判定：通过） |
| `docs/reviews/templates/REVIEW-TEMPLATE.md` | 报告模板 |
| `tools/gate.py` | 自动门禁脚本 |
| `.gitignore` | 补建（原缺失，红线 V8 风险） |

**监制核心原则**：信产物不信汇报；门禁必须可复现；一票否决不商量；驳回对事不对人。
**独立性边界**：监制不替开发 Agent 改业务代码，只出报告要求返工。

**gate.py 设计要点**：
- 检查维度：结构 / 工程卫生 / 密钥泄露(V1) / 代码卫生 / 架构违规(V7) / 风险用法
- 阶段模型：stage 0~9，与指令文件阶段一一对应
- 用法：`python tools/gate.py --stage N [--build] [--json out.json] [--list]`
- 退出码 0=通过 1=FAIL 2=脚本错误
- 已做**对抗性验证**：注入 6 类违规样本（密钥/debugger/dbg!/硬编码路径/UI直连库/插件直连库）全部命中
- 自豁免机制：`tools/` 目录不参与卫生与风险扫描（脚本内含正则字面量与 print 输出，否则永远自我误报）

**当前进度**：阶段0 通过了基线审核；阶段1~9 全部未开始。
**两个未决遗留项**：L-001 源计划书 txt 已不在工作区（建议归档 docs/source/）；L-002 ADR-001 未定稿（**阻塞阶段3**）。

## 建立 Agent 交接机制（白宇问"怎么交接给别的 agent 接手"）

**产出**：
- `HANDOFF.md`（仓库根）—— 交接总入口，10 章：30 秒状况表 / 下一步任务 / 必读3份 / **环境与已知的坑** / 红线速览 / 送审规则 / 阶段地图 / 冷启动自检三问 / 交接检查单 / **复制粘贴给新 Agent 的开场白（可直接整段发）** / 交接本质
- `AGENTS.md`（仓库根）—— 指针文件，给"只自动读仓库根 AGENTS.md"的工具兜底

**关键设计**：
1. 交接固化的三样隐形知识：现在到哪一步（LEDGER）、哪些坑会白干半天（环境坑）、哪些事会被打回（红线+送审规则）。
2. **冷启动自检三问**：新 Agent 必须能答"唯一写入者是谁 / 为什么窗口管理排在模式引擎前 / 插件默认有无权限"——用来验证它是真接手了还是假读了。
3. `HANDOFF.md` 里内置一段**可直接复制粘贴的开场白**，含六步命令与全部硬约束，任何模型适用。
4. 门禁 `BASELINE_REQUIRED` 已加入 `HANDOFF.md` / `AGENTS.md` / `tools/gate.py`——交接设施缺失即 FAIL，不靠自觉维护。
5. 核心原则：**状态外置**——进度写在台账里，不依赖任何 Agent 的记忆；换 Agent 不换状态。

**验证**：门禁重跑 PASS=10 / FAIL=0。

**确认事实**：两份源计划书 txt 已确实不在工作区（glob `**/*.txt` 无结果），L-001 仍开放。
