1. **`ai/assistant/` 镜像 `ai/model/` 的既有分层**：纯函数层（session/request）+ 传输端口（transport）+ 服务（service）+ 组合根（bridge）。

## TECH-06-A · AI 模型真实连接完善

**交付**：`docs/tech/TECH-06-A-ui-model-real-connection.md` · 审计 `docs/tech/TECH-06-A-audit.md`
· 验收 `tools/verify_tech06a.py` **43/43**（FAIL=0，跑在最终 `ui/dist` 上）

### 审计先于编码 —— 结论改变了做法

审计最重要的一条：**链路本来就是真的**（`registry.check` → 三 Adapter → `ai_list_models` →
sidecar `/ai/models` 真 HTTP），**失真的是"状态语义"**：
`entryStatusOf()` 把 `lastError` 一律折成 `unavailable`，页面再把它显示成「不可用」——
**「离线」（本地服务没起）与「连接失败」（鉴权/超时/限流）被糊成一个词**，信息在归约时就丢了。
所以本轮**不建任何新设施**，只做四件事：语义去失真 / 列表透出证据 / 补 Agent 一类探测 / 堵一个假绿入口。

### 状态归约是两段，以前只落地了第一段（可复用的模型）

```
ModelProfile.status ─entryStatusOf()→ ready|unchecked|unavailable|disabled   （既有，领域内部态）
                    ─displayStatusOf()→ connected|unconfigured|failed|offline|unchecked  （本轮新增，唯一出处）
```
第二段以前散在页面（`ModelsView.vue` 的 `STATUS_LABEL`）→ 页面成了判据实现方。
新增 `ui/src/ai/model/status.ts`（纯函数 / 零 IO / 零框架 import）把它收成唯一出处，
页面降级为**消费方** —— 顺带使验收能用 Node 直接穷举归约（288 组合）。
**判据顺序即优先级**：未启用→offline｜需 key 无凭据→unconfigured（缺前提，请求发不出去）｜
ready→connected（唯一正向）｜unchecked→unchecked（不猜）｜失败码分流 offline/failed。

### 三个可复用的工程要点

1. **"新能力"常常只是"旧能力没接线"**：Agent 连接检测直接复用 core **既有** `agents_list` + `agent_health`
   （`core/src/agents.rs:121/209` 早就在做真实 `GET {url}{healthCheck}`，只是 UI 只在 `pluginService.ts` 包了壳）。
   → **零新增后端命令**。做法：给 `ModelIo` 加**可选** `agentHealth?`，`AgentAdapter` 真探测。
2. **假绿的修法是"让错误更响"**：`coreModelIo.listRemoteModels` 无 core 时原来是 `return []`，
   而 Adapter 把"没抛错"当 `ok:true` ⇒ 显示「已连接 · 0 个模型」。改成**抛错**（`unreachable`）→ 如实报「离线」。
3. **`ModelListEntry` 透出证据才谈得上"显示真实"**：加 `needsSecret`/`lastError`/`lastCheck`（**加法**），
   页面不再自查 Provider 表（`needsSecret` ← L0 能力真相 `getProvider().needsKey`）。

### 两条踩坑记录（脚本层，血泪）

- **`strip_comments` 之后，注释里的词不算证据**：T3c 断言写成 `"probed" in abody`，
  而 `probed` 只出现在被剥掉的注释里 —— 它实际是 `result()` 的**第 7 个位置参数**（源码无同名标识符）。
  → 静态断言凡涉及"函数返回了什么"，**要么按位置数实参，要么承认它只存在于运行期**，别指望标识符名。
