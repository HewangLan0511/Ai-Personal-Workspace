# 01 · 项目上下文（Agent 必读背景）

> 目的：让你在写第一行代码之前，知道自己在做**什么**、**给谁做**、**什么算成功**。

---

## 1.1 项目要解决的问题

个人电脑里的软件、文件、网页服务不断堆积，传统桌面环境存在五个痛点：

1. **软件分散** —— 找东西靠翻目录
2. **窗口切换频繁** —— 靠 Alt+Tab 硬切
3. **信息来源割裂** —— 资料在文件夹、笔记在别处、AI 在浏览器
4. **学习/工作/生活缺乏统一管理** —— 每个场景各搭一套
5. **AI 工具无法真正融入个人工作流** —— AI 是"另一个网页"，不是工作环境的一部分

现有方案（桌面快捷方式、文件夹分类、浏览器收藏、Alt+Tab、多个独立 AI 工具）的共同缺陷：**全部要求用户主动组织环境**。

## 1.2 产品定位

Personal Workspace **不是**：

- ❌ 软件启动器
- ❌ 信息管理软件
- ❌ 单纯的 AI 聊天工具

Personal Workspace **是**：

- ✅ 个人数字调度中心
- ✅ 工作环境编排系统
- ✅ 动态成长档案系统
- ✅ AI 辅助个人空间

> 一句话：**从"人适应电脑"变成"电脑适应人"。**

## 1.3 核心目标（唯一的北极星）

用户点一个工作模式：

```
点击「深度学习模式」
        ↓
系统自动执行：
  1. 启动相关软件      （VS Code / Chrome / PDF / Terminal）
  2. 打开文件入口      （学习资料目录、项目目录）
  3. 调整窗口布局      （四宫格 + AI 侧栏）
  4. 加载 AI 助手      （技术助手，带权限）
  5. 展示相关信息      （当前项目、学习进度）
        ↓
结果：「进入状态即可工作」
```

**这个闭环是本项目唯一的创新点。** 其他所有模块都是围绕它服务的生态。任何时候资源冲突，优先保证这个闭环。

## 1.4 目标用户（用来自检的判断标准）

一个有长期学习/开发计划的个人用户，特征是：

- 电脑上装了 30 个以上软件，切换场景靠手动
- 同时推进多个项目/学习路线，状态散落各处
- 愿意用 AI，但不想每次复制粘贴上下文
- **在意本地数据和隐私**，不接受"什么都上云"

自检问题：*"这个功能会让上面这个人在切换场景时少点几下鼠标吗？"* 如果不能，优先级往后放。

## 1.5 三层架构（心里要有这张图）

```
┌────────────────────────────────────────────┐
│  第三层 · 扩展层                            │
│  插件 / 第三方 Agent / 外部服务             │
├────────────────────────────────────────────┤
│  第二层 · 功能生态层                        │
│  AI助手 / 学习成长 / 项目管理 / 生活服务    │
│  / 设备管理 / 个人档案                      │
├────────────────────────────────────────────┤
│  第一层 · 工作空间调度层（CORE ⭐）         │
│  工作模式 / 软件组合 / 窗口布局 / 状态管理  │
│  软件管理 · 文件入口 · 插件宿主 · 窗口管理  │
└────────────────────────────────────────────┘
```

**依赖方向只能是自下而上**：第一层不认识第二层的具体业务，第二层通过接口调用第一层。第三层只能调前两层暴露的 API。

## 1.6 成功判据

MVP 阶段结束时，必须能做到：

| 判据 | 衡量方式 |
|------|----------|
| 冷启动到可用 | 应用启动 < 3s，界面无白屏 |
| 一键进入环境 | 点击模式后 10s 内软件全部拉起、窗口排列到位 |
| 手动操作减少 | 同一个场景切换，操作步骤比手动少 70% 以上 |
| 数据本地 | 断网可用（除 AI 调用），数据全在本机 SQLite |
| 可扩展 | 新增一个插件不改动核心代码 |
| 不绑定模型 | 换一个 AI Provider 只需改配置，不改业务代码 |

## 1.7 明确不做的事（范围边界）

- 不做云端账号体系（V1/V2 无服务器）
- 不做文件内容存储与云同步
- 不做 IM 消息内容抓取与保存（社交模块只做"概览"）
- 不做跨平台移动端
- 不做游戏内注入/外挂类功能（娱乐模式只做"启动 + 分析"）
- 不在第一阶段做多机设备管理（只管本机）

超出以上范围的实现，即使技术上可行，也视为**需求蔓延**，需要先确认。

## 1.8 给 Agent 的上下文速记卡

```
我在做什么：把两个计划书变成一个真能跑的桌面应用
核心技术判断：Tauri + Vue3 + TS 为壳，Rust 做调度核心，Python 做系统调用与 AI
核心创新：工作模式引擎 —— 一个模式 = 软件 + 文件 + 布局 + AI 的完整环境快照
最重要的一句话：点击一次，进入工作状态
最怕的事：为了炫技把核心做复杂，或者跳过工作模式引擎先做花架子
```
