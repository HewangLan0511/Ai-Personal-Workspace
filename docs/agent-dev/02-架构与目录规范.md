# 02 · 架构与目录规范（硬约束）

> 本文件定义的目录结构与分层规则是**强制**的。违反即视为交付不合格。

---

## 2.1 技术栈（已定，不要擅自更换）

| 层 | 选型 | 说明 |
|----|------|------|
| 桌面壳 | **Tauri 2.x**（首选） / Electron（备选） | 优先 Tauri：性能高、内存占用低、原生能力强 |
| 前端 | **Vue 3 + TypeScript + Vite** | UI、Dashboard、工作模式界面 |
| 核心层 | **Rust** | 状态管理、调度、窗口控制、数据库写入、插件宿主 |
| 系统调用 | **Python 3.11+**（sidecar） | 进程/窗口/媒体/设备等系统级操作、AI 调用、数据处理 |
| 数据库 | **SQLite** | 配置 / 工作模式 / 档案 / 学习 / 插件 |
| 通信 | **本地 HTTP + WebSocket（127.0.0.1）** + **Event Bus** | 模块间解耦 |

**为什么 Rust + Python 同时存在？**
Rust 负责"稳和快"（常驻、状态、窗口句柄持有），Python 负责"快和广"（生态丰富的系统 API 与 AI SDK）。两者职责**必须**边界清晰，见 2.4。

## 2.2 目录结构（强制）

> **与 ADR-001 的同步说明（2026-09-12，L-005）**：窗口控制与进程启动已定稿为 **Rust**，
> 故 `system/win/` **不存在** `process.py` / `window.py`；`core/src/` 新增 `api/`（HTTP + Tauri
> command 接口面）与 `sidecar/`（sidecar 生命周期），二者属架构师裁量新增，已在 `core/README.md` 登记。

```

│   │   ├── app_manager/        # 软件注册、启动、状态检测（ADR-001 = Rust）
│   │   ├── window_manager/     # 窗口枚举、定位、尺寸、激活（ADR-001 = Rust）
│   │   ├── sidecar/            # Python sidecar 拉起 + 健康检查 + 崩溃重启
```

**目录红线**：
- `core/` 不得依赖 `modules/`、`plugins/`、`ui/`
- `plugins/` 不得直接访问数据库，只能通过宿主提供的 Data API
- `ui/` 不得直接读写 SQLite，一律走 `api/` 封装
- `system/` 不得直接写数据库，只提供服务能力

## 2.3 三层职责清单

| 层 | 拥有 | 不负责 |
|----|------|--------|
| **Core** | 状态机、模式调度、窗口句柄、数据库、事件总线、插件宿主 | 业务语义（什么是"学习进度"它不懂） |
| **Modules** | 业务逻辑与 UI（学习路线、档案、生活服务） | 系统调用、直接操作窗口 |
| **Plugins** | 自己那点功能的逻辑与 UI | 越权访问、改核心状态 |

## 2.4 Rust / Python 边界（最容易乱，重点记）

**唯一的数据库写入者是 Rust core。** Python 一律通过 core 提供的本地接口读写数据。

```
┌──────────┐   HTTP/JSON-RPC    ┌──────────────┐
│ Python   │ ─────────────────► │  Rust core   │
│ sidecar  │ ◄───────────────── │  /db/...     │
└──────────┘   返回结果          │  SQLite 写入 │
      │                          └──────────────┘
      │ 系统 API（进程/窗口/媒体/性能）
      ▼
   Windows OS
```

职责划分：

| 能力 | 归属 | 理由 |
|------|------|------|
| 应用状态、模式状态 | Rust | 常驻内存，需要被多处读取 |
| 窗口句柄持有与布局 | Rust（调 windows crate）**或** Python（pywin32） | **二选一，项目内统一，不得混用** |
| 启动进程 | 二选一，同上 | 同上 |
| 媒体会话、性能计数 | Python | winsdk / psutil 生态成熟 |
| AI Provider 调用 | Python | SDK 生态与流式处理更方便 |
| 数据处理与清洗 | Python | —— |
| 插件加载与权限校验 | Rust | 安全边界必须在核心里 |

> 决策记录：窗口控制与进程启动的实现语言，在 `04-阶段指令-基础框架.md` 中作为 ADR-001 定稿后写入 `config/app.toml` 注释，后续不得随意切换。

## 2.5 命名与编码规范

| 对象 | 规范 | 示例 |
|------|------|------|
| 目录 | kebab-case | `window-manager`（插件目录）、`ai-provider` |
| Rust 文件 | snake_case | `window_manager.rs` |
| Rust 类型 | PascalCase | `ModeScheduler` |
| Vue 组件 | PascalCase | `ModeCard.vue` |
| TS 变量/函数 | camelCase | `applyLayout()` |
| Python | snake_case | `launch_app()` |
| 数据库表 | snake_case 复数 | `work_modes`、`apps` |
| 数据库字段 | snake_case | `created_at` |
| 事件名 | SCREAMING_SNAKE | `MODE_CHANGED` |
| 权限名 | `domain:action` | `app:launch`、`file:read` |
| 插件 ID | 反向域名 | `com.example.music` |
| 布局文件 | kebab-case.json | `study.json`、`coding.json` |

**禁止**：散落的魔法字符串（事件名、表名、权限名必须集中在常量模块）；同一含义多个名字（如 `mode` / `workspace` / `scene` 混用）。

## 2.6 模块间通信：Event Bus

所有跨模块通知**必须**走事件总线，禁止模块间直接函数调用耦合。

```ts
// 示例：订阅模式切换
bus.on('MODE_CHANGED', ({ modeId, apps }) => { /* 刷新 Dashboard */ })
```

事件清单（完整定义见 `03-数据契约与接口规范.md`）：

```
MODE_CHANGED          MODE_APPLY_PROGRESS      MODE_APPLY_FAILED
APP_REGISTERED        APP_OPENED               APP_CLOSED
WINDOW_LAYOUT_APPLIED WINDOW_LAYOUT_FAILED
AI_REQUEST            AI_STREAM_CHUNK          AI_RESPONSE
LEARNING_PROGRESS_UPDATED
PROFILE_UPDATED
PLUGIN_LOADED         PLUGIN_ERROR             PLUGIN_PERMISSION_DENIED
CONFIG_CHANGED        DEVICE_METRICS_UPDATED
```

规则：
1. 事件必须是**过去时**（已发生的事实，不是命令）。
2. 事件 payload 必须可序列化（JSON），禁止传函数或句柄。
3. 发起方不等待订阅方返回。
4. 事件 schema 变更必须同步更新 `03-数据契约与接口规范.md`。

## 2.7 错误处理与降级原则

- **局部失败不能拖垮整体**：某个软件启动失败 → 记录 + 继续拉起其余软件 + 在 UI 上标注该项失败，**不要整体回滚**。
- **超时必须有**：进程启动 15s、窗口定位 5s、AI 请求按 Provider 配置。
- **可重试**：窗口定位这类偶发失败允许自动重试 2 次。
- **用户可读**：错误信息写"Chrome 启动失败（路径不存在：C:\...）"，不写 `Err(Os { code: 2 })`。

## 2.8 安全与隐私基线

- 敏感信息（API Key）→ 系统凭据库（Windows Credential Manager），**不进 SQLite、不进 git**。
- 插件默认**零权限**，权限由用户授权后写入 `plugin_permissions` 表。
- 文件访问限定在用户显式添加的目录内。
- 社交模块**只读概览、不落库消息内容**。
- 遥测默认关闭，无网络回传（除用户主动调用的 AI 与天气等显式外部服务）。

## 2.9 自检清单

写完一个模块，对着问：

- [ ] 我的代码在正确的层吗？（core 里有没有业务语义？ui 里有没有直接读库？）
- [ ] 有没有绕过 Event Bus 直接互相调用？
- [ ] 有没有硬编码路径、密钥、模型名？
- [ ] 数据库写入是不是只发生在 core？
- [ ] 失败时会不会把整个流程拖死？
- [ ] 事件名、表名、权限名是不是走的常量？
