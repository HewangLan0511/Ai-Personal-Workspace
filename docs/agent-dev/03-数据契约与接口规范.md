# 03 · 数据契约与接口规范

> 本文件是**唯一数据真相来源**。任何新增的表、JSON 结构、事件、HTTP 接口，都必须先在此登记，再写代码。
> 修改本文件需要同步升级 `schema_version`。

---

## 3.1 SQLite 数据表

约定：
- 所有表带 `id INTEGER PRIMARY KEY AUTOINCREMENT`、`created_at`、`updated_at`（TEXT，ISO8601）。
- 所有软删除字段：`deleted_at TEXT NULL`。
- 时间统一存本地时区 ISO8601 字符串，不存时间戳整数。
- 迁移脚本放 `core/migrations/`，命名 `0001_init.sql`、`0002_xxx.sql`，**只增不改**。

### config —— 应用配置（KV）
```sql
CREATE TABLE config (
  key         TEXT PRIMARY KEY,
  value       TEXT NOT NULL,          -- JSON 字符串
  updated_at  TEXT NOT NULL
);
```

#### 3.1.1 config 键登记表（权威清单）

> 代码侧的权威实现是 `core/src/db/config.rs` 的 `KEYS`/`expected_type`/`default_for`；
> `ConfigService::set` 会**拒绝未登记的键**与类型不符的值。新增键必须同时改此处与代码，
> 并按 §3.5 升 `schema_version`。

| 键 | 类型 | 默认值 | 说明 | 可被 UI 写 |
|----|------|--------|------|:----------:|
| `schema_version` | number | 0 | **数据契约版本**（非迁移台账，见 §3.5 注）；由 `db::initialize` 按 `CONTRACT_SCHEMA_VERSION` 写入 | ❌ |
| `ui.theme` | string | `"light"` | `light` / `dark` | ✅ |
| `ui.nav.collapsed` | boolean | `false` | 左侧导航折叠状态（04 §2「折叠状态持久化」） | ✅ |
| `ui.dashboard.widgets` | array | `[]` | Widget 清单（`Widget[]`，见 3.2） | ✅ |
| `ui.dashboard.usage` | object | `{}` | `{ [widgetId]: 使用次数 }`（04 §3 动态布局依据） | ✅ |
| `ui.dashboard.layout_locked` | boolean | `false` | 用户是否手动调过布局；`true` 时不再自动改尺寸 | ✅ |
| `app.autostart` | boolean | `false` | 开机自启 | ✅ |
| `app.data_dir` | string | `""` | 数据目录（空 = 默认 `%APPDATA%/PersonalWorkspace`） | ✅ |
| `ai.default_provider` | string | `""` | 默认 AI Provider 名 | ✅ |
| `privacy.telemetry` | boolean | `false` | 匿名遥测开关，默认关 | ✅ |
| `runtime.sidecar_port` | number\|null | `null` | sidecar 实际监听端口（启动时写入） | ❌ |
| `runtime.http_port` | number\|null | `null` | core HTTP 实际监听端口（随机端口，启动时写入） | ❌ |
| `db.migration_version` | number | 无（首次运行时写） | **迁移台账**，记录已执行的 DDL 脚本序号；内部使用，不登记进 `KEYS`、不对外暴露 | ❌ |

> **口径说明**：`schema_version`（契约版本，03 文档管）与 `db.migration_version`（迁移台账，
> `core/migrations/` 管）是**两个不同的键**。混用一个键会导致"契约版本被迁移序号覆盖"，
> 且迁移升级判据失真（REVIEW-002 R-01 / L-006 即此问题）。

### apps —— 软件注册表
```sql
CREATE TABLE apps (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  name        TEXT NOT NULL,
  path        TEXT NOT NULL UNIQUE,   -- 可执行文件或快捷方式路径
  args        TEXT DEFAULT '',        -- 启动参数
  icon        TEXT,                   -- 图标文件路径或 base64
  type        TEXT,                   -- dev/browser/office/media/game/other
  category    TEXT,                   -- 用户自定义分类
  launch_count INTEGER DEFAULT 0,     -- 启动次数（用于频率排序）
  last_used_at TEXT,
  created_at  TEXT NOT NULL,
  updated_at  TEXT NOT NULL,
  deleted_at  TEXT
);
CREATE INDEX idx_apps_category ON apps(category);
CREATE INDEX idx_apps_launch_count ON apps(launch_count DESC);
```

## 3.2 JSON 结构契约

### 3.2.1 工作模式（`work_modes` 的序列化形态）
```json
{
  "name": "AI开发模式",
  "description": "写代码时的一整套环境",
  "apps": ["VSCode", "Chrome", "Terminal"],
  "openTargets": [
    { "path": "D:/projects/my-app", "label": "项目目录", "type": "folder" },
    { "path": "D:/docs/spec.md", "label": "需求文档", "type": "file" }
  ],
  "layout": "coding.json",
  "aiProfile": {
    "provider": "deepseek",
    "systemPromptKey": "dev_assistant",
    "permissionScope": ["file:read", "app:launch"]
  },
  "autoApply": false
}
```

### 3.2.2 窗口布局
```json
{
  "name": "coding",
  "monitor": 0,
  "slots": [
    {
      "app": "VSCode",
      "rect": { "x": 0.0, "y": 0.0, "w": 0.5, "h": 1.0 },
      "z": 1,
      "alwaysOnTop": false,
      "maximized": false
    },
    {
      "app": "Chrome",
      "rect": { "x": 0.5, "y": 0.0, "w": 0.5, "h": 0.5 },
      "z": 2
    },
    {
      "app": "Terminal",
      "rect": { "x": 0.5, "y": 0.5, "w": 0.5, "h": 0.5 },
      "z": 3
    }
  ],
  "aiSidebar": { "enabled": true, "edge": "right", "width": 0.2 }
}
```

**规则**：
- `rect` 使用 **0~1 归一化坐标**，相对于目标显示器工作区（不含任务栏），由 core 负责换算成像素。这样换显示器/改分辨率时布局不崩。
- `z` 越小越靠后（先激活大窗口）。
- 应用未启动成功时，其 slot 跳过，**不阻塞其余窗口**。
- `aiSidebar` 属于应用自身窗口，不参与外部窗口管理。

## 3.3 Event Bus 事件表

统一 payload 外层：`{ "event": "MODE_CHANGED", "ts": "2026-09-12T17:30:00+08:00", "payload": { ... } }`

| 事件 | payload | 触发时机 |
|------|---------|----------|
| `MODE_CHANGED` | `{ modeId, name, apps }` | 模式切换成功 |
| `MODE_APPLY_PROGRESS` | `{ modeId, step, total, detail }` | 应用模式过程中的进度 |
| `MODE_APPLY_FAILED` | `{ modeId, step, reason, recoverable }` | 某一步失败（不中断整体） |
| `APP_REGISTERED` | `{ appId, name, path }` | 添加软件成功 |
| `APP_OPENED` | `{ appId, pid, hwnd }` | 进程启动成功 |
| `APP_CLOSED` | `{ appId, pid, exitCode }` | 进程退出 |
| `WINDOW_LAYOUT_APPLIED` | `{ layout, monitor, slots }` | 布局应用完成 |
| `WINDOW_LAYOUT_FAILED` | `{ layout, app, reason }` | 单个窗口定位失败 |
| `AI_REQUEST` | `{ conversationId, provider, mode }` | 发起 AI 请求 |
| `AI_STREAM_CHUNK` | `{ conversationId, delta }` | 流式返回片段 |
| `AI_RESPONSE` | `{ conversationId, tokens, durationMs }` | 请求结束（**不含正文**） |
| `LEARNING_PROGRESS_UPDATED` | `{ goalId, nodeId, status }` | 学习状态更新 |
| `PROFILE_UPDATED` | `{ section, changedFields }` | 档案更新（含 AI 建议待确认） |
| `PLUGIN_LOADED` | `{ pluginId, version }` | 插件加载成功 |
| `PLUGIN_ERROR` | `{ pluginId, reason }` | 插件崩溃/加载失败 |
| `PLUGIN_PERMISSION_DENIED` | `{ pluginId, permission, scope }` | 越权访问被拦截 |
| `CONFIG_CHANGED` | `{ key, oldValue, newValue }` | 配置项变更 |
| `DEVICE_METRICS_UPDATED` | `{ cpu, gpu, memUsed, memTotal }` | 设备指标刷新（默认 2s） |

## 3.4 本地 HTTP 接口（core ↔ python ↔ ui）

统一前缀 `/api/v1`，返回 `{ ok: boolean, data?: any, error?: { code, message } }`。

### core 暴露给 Python sidecar
| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/internal/db/query` | 只读查询（参数化 SQL，禁止任意 SQL 拼接） |
| POST | `/internal/db/exec` | 写入（仅限白名单表） |
| POST | `/internal/event/publish` | 发布事件到总线 |
| GET  | `/internal/config/{key}` | 读配置 |
| POST | `/internal/cache/set` | 写缓存（内存，不落库） |

### Python sidecar 暴露给 core
| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/sys/process/launch` | 启动进程，返回 `{ pid }` |
| POST | `/sys/process/status` | 查询进程是否存活 |
| POST | `/sys/window/find` | 按 pid/标题找窗口，返回 `{ hwnd, rect }` |
| POST | `/sys/window/set` | 定位窗口（x/y/w/h、激活、置顶） |
| GET  | `/sys/media/current` | 当前播放媒体信息 |
| GET  | `/sys/perf/metrics` | CPU/GPU/内存 |
| POST | `/ai/chat` | 统一 AI 调用（provider 由参数指定，支持 stream） |
| GET  | `/health` | 健康检查 |

### UI 调用（经 Tauri command 或 /api/v1）

> **首选 Tauri command 通道**：core 的 HTTP 是**随机端口**，而 UI 被红线 V7 禁止读 SQLite、
> 拿不到该端口（写死端口又违反 04 §5）——故 UI 主路径走 `invoke`，HTTP 仅作浏览器调试兜底。
> 已登记的 command：`ping`（探活）· `get_config(key)` · `put_config(key, value)` · `minimize_window()`。
> 二者语义等价，均以 `{ ok, data, error }` 为约定（command 侧失败即 reject，成功直接返回 data）。

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/v1/config/{key}` | 读取单个配置项（返回 JSON 值；不存在返回默认值） |
| PUT | `/api/v1/config/{key}` | 写入配置项（body 为 JSON 值；触发 `CONFIG_CHANGED`） |
| GET | `/api/v1/modes` `/api/v1/modes/{id}` | 工作模式 |
| POST | `/api/v1/modes/{id}/apply` | ★ 应用模式（核心动作） |
| GET/POST/DELETE | `/api/v1/apps` | 软件管理 |
| GET/POST | `/api/v1/layouts` | 布局管理 |
| POST | `/api/v1/ai/chat` | AI 对话（stream） |
| GET/POST | `/api/v1/learning/goals` | 学习目标 |
| GET/POST | `/api/v1/profile` | 档案 |
| POST | `/api/v1/plugins/{id}/enable` | 插件启停 |

## 3.5 契约变更流程

1. 先改本文件（表 / JSON / 事件 / 接口 / config 键）。
2. 升级 `schema_version`（在 `config` 表里）—— 同时改代码常量 `migrations::CONTRACT_SCHEMA_VERSION`。
3. 写 migration（若涉及表结构）。
4. 同步更新调用方。
5. 在本文件底部「变更记录」追加一行。

> **注 · 两个版本号不要混用（L-006）**
> - `config.schema_version` = **数据契约版本**（本文档管，当前 v3）；
> - `config.db.migration_version` = **迁移台账**（`core/migrations/` 管，记录已执行的 DDL 脚本序号）。
> - 不涉及表结构变更时**只升契约版本，不写 migration**。

### 变更记录
| 日期 | 版本 | 变更 | 影响 |
|------|------|------|------|
| 2026-09-12 | v1 | 初版契约（由计划书 V1.0 转化） | —— |
| 2026-09-12 | v2 | 补登记 UI 配置读写接口 `GET/PUT /api/v1/config/{key}`（阶段1 ConfigService 需要，原契约仅覆盖 Python 侧 `/internal/config`）；定稿 ADR-001（窗口控制/进程启动 = Rust）。`schema_version` = 2 | UI api 层、core ConfigService |
