# 03 · 数据契约与接口规范

> 本文件是**唯一数据真相来源**。任何新增的表、JSON 结构、事件、HTTP 接口，都必须先在此登记，再写代码。
> 修改本文件需要同步升级 `schema_version`。

---

## 3.1 SQLite 数据表

约定：
- 所有表带 `id INTEGER PRIMARY KEY AUTOINCREMENT`、`created_at`、`updated_at`（TEXT，ISO8601）。
- 所有软删除字段：`deleted_at TEXT NULL`。
- 时间统一存本地时区 ISO8601 字符串，不存时间戳整数。
- 迁移脚本放 `core/migrations/`，命名 `0001_init.sql`、`0002_xxx.sql`，**只增不改**。

> **注 · canonical 与过渡镜像的关系（TECH-04 §一）**
> `ai.provider.current` / `ai.model.current` 是冻结契约指定的 **canonical（L1）落点**，
> 即"当前用哪个模型"的**唯一事实来源**。阶段5 起 UI 还在写 `ui.ai.provider` / `ui.ai.model`
> 这两个**过渡镜像键**，TECH-04 **刻意保留**它们：
> ① 前端 `localStorage` 兜底与 core 副本必须同构（见下方 `ui.ai.*` 注）；
> ② 老数据（只写过镜像的用户）仍能读出来。两者关系是**"落点 + 兼容副本"**，
> 不是两个并列来源：启动时 canonical 优先，canonical 为空才用镜像，
> 且**一次性前向搬运**到落点（`ui/src/ai/model/bridge.ts::migrateIfNeeded()`，不删旧值）。
> 该口径由 `tools/verify_tech04.py` 机器验证。


> **注 · `ui.ai.*` 为什么是 string 而不是 number/boolean**（阶段5）：
> 侧栏这五项同时落在两处 —— 前端 `localStorage`（`ui/src/stores/ai.ts`）与 core 的 `config` 表。
> `localStorage` **只能存字符串**，故 core 侧作为**权威副本**与之同构（否则"写 A 读 B"必然对不上）。
> 类型由 `ConfigService::expected_type` 强制校验，键未登记会被拒写。

> **口径说明**：`schema_version`（契约版本，03 文档管）与 `db.migration_version`（迁移台账，
> `core/migrations/` 管）是**两个不同的键**。混用一个键会导致"契约版本被迁移序号覆盖"，
> 且迁移升级判据失真（REVIEW-002 R-01 / L-006 即此问题）。

### apps —— 软件注册表
```sql
CREATE TABLE apps (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  name        TEXT NOT NULL,
  path        TEXT NOT NULL UNIQUE,   -- 可执行文件或快捷方式路径
  args        TEXT DEFAULT '',        -- 启动参数
  icon        TEXT,                   -- 图标缓存**文件路径**（禁止存二进制，05 §禁止事项）
  type        TEXT,                   -- dev/browser/office/media/game/other
  category    TEXT,                   -- 预置或用户自定义分类
  launch_count INTEGER DEFAULT 0,     -- 启动次数（用于频率排序）
  last_used_at TEXT,
  pinned      INTEGER DEFAULT 0,      -- 用户置顶（05 §4；由迁移 0002 追加）
  created_at  TEXT NOT NULL,
  updated_at  TEXT NOT NULL,
  deleted_at  TEXT                    -- 软删除标记（不物理删行）
);
CREATE INDEX idx_apps_category ON apps(category);
CREATE INDEX idx_apps_launch_count ON apps(launch_count DESC);
CREATE INDEX idx_apps_pinned ON apps(pinned DESC);
```

> **排序契约（05 §4）**：列表固定按 `pinned DESC → launch_count DESC → last_used_at DESC → name ASC`。
> Dashboard「常用软件」Widget **直接消费这个顺序**，不得在前端另行排序。

### learning_goals / learning_roadmap / learning_updates / projects —— 学习成长与项目（阶段6）
```sql
CREATE TABLE learning_goals (

  sort_order   INTEGER DEFAULT 0,      -- 1..n 连续；增删/调序后由 repo 重排
  completed_at TEXT,                   -- 进入 done 时补写；离开 done 清空
  created_at   TEXT NOT NULL,
  updated_at   TEXT NOT NULL
);

CREATE TABLE learning_updates (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  goal_id    INTEGER NOT NULL REFERENCES learning_goals(id),
  node_id    INTEGER REFERENCES learning_roadmap(id),

  created_at TEXT NOT NULL
);

CREATE TABLE projects (               -- 阶段6 §6（迁移 0005）
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  name       TEXT NOT NULL,
  role       TEXT,                             -- 承担角色
  summary    TEXT,
  tech_stack TEXT,                             -- JSON 数组
  start_date TEXT,
  end_date   TEXT,
  status     TEXT NOT NULL DEFAULT 'ongoing',  -- ongoing|paused|done
  directory  TEXT,                             -- 关联目录
  mode_name  TEXT,                             -- ★ 绑定的工作模式名（与核心的联动点）
  goal_id    INTEGER REFERENCES learning_goals(id),  -- 完成项目 = 提议达成目标

  updated_at TEXT NOT NULL,

CREATE INDEX idx_projects_mode   ON projects(mode_name);
CREATE INDEX idx_projects_status ON projects(status);
CREATE INDEX idx_projects_goal   ON projects(goal_id);
```

> **注 · `roadmap` 列名与 `roadmapRaw` 的差异不是笔误**：库里的列叫 `roadmap`（0001 建表时就定了），
> Rust 侧结构体字段叫 `roadmap_raw`、序列化成 `roadmapRaw`。契约以**序列化名**为准（前端按它取值）。
> 这一列存的是**模型原文快照**（供"降级为文本展示"与"重新生成时对比"），
> **不是**结构化路线的落点 —— 结构化节点必须在 `learning_roadmap` 的列里（09 §禁止事项第 4 条）。

> **注 · `projects` 与 `profile_projects` 是两个实体**（迁移 0005 的注释同口径）：
> `projects` = 正在做/要做的事（有目录、可绑模式、可挂学习目标）；`profile_projects` = 档案里的**经历条目**（阶段7）。
> 混用会让"进行中的项目"与"已入职历的经历"语义打架。

> **注 · 阶段6 不变量（红线 V3，代码结构上保证）**：**没有任何一条从 AI 到本组表的写入路径**。
> AI 建议（`learning::ai_suggest`）只读不写，产出带 `advisory: true`；要落库必须由用户动作
> 经 `learning_roadmap_confirm` / `learning_node_*` / `learning_goal_*` / `project_*` 触发。
> 该不变量由 `tools/verify_stage6.py` 验收项 6 端到端断言（调用前后对四张表做全行快照比对）。

**pending_suggestions（阶段7 迁移 0006 新增）—— 待确认建议队列（10 §5 的 ★ 用户确认 ★ 硬关口）**：
```sql
CREATE TABLE pending_suggestions (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  kind       TEXT NOT NULL,                     -- timeline | skill | project
  ref_key    TEXT NOT NULL,                     -- 去重键，如 "goal_done:3" / "app_hot:Code"
  title      TEXT NOT NULL,                     -- 给用户看的一句话
  payload    TEXT NOT NULL,                     -- JSON：确认时写入对应档案表的数据
  status     TEXT NOT NULL DEFAULT 'pending',   -- pending | confirmed | ignored
  created_at TEXT NOT NULL,
  decided_at TEXT
);
CREATE INDEX idx_pending_status ON pending_suggestions(status, kind);
CREATE UNIQUE INDEX idx_pending_unique_open      -- 部分唯一索引：同源只挂一条 pending
  ON pending_suggestions(kind, ref_key) WHERE status = 'pending';
```

> ⚠️ **红线 V3 的表级落实**：采集器/AI 只允许 INSERT 本表（`status='pending'`），
> **没有任何一条从 AI 到档案四表的写路径** —— 档案四表只被"用户手动编辑"与
> "确认建议（`suggestion_confirm`）"写入。`payload` 按 kind 分发：
> `timeline` → `profile_timeline` 行；`skill` → `profile_skills`（UPSERT by name）；
> `project` → `profile_projects` 行。

**plugin_audit（阶段9 迁移 0008 新增）—— 插件与外部 Agent 审计日志（12 §A3/C4）**：

### usage_stats —— 屏幕使用时间（生活中心 / 健康，**阶段8 迁移 0007 落地**）
```sql
CREATE TABLE usage_stats (
  day      TEXT    NOT NULL,             -- YYYY-MM-DD（本地日期）
  app_name TEXT    NOT NULL,             -- 前台进程名（小写，去 .exe）

```
> **只存聚合结果**（按 天+应用 累加），不存前台切换的时间点明细（11 §A4 数据轻量化）。
> 原预设结构（`id`/`stat_date`/`foreground_s`）在阶段8 实现时简化为上述三列主键形态。

### ai_conversations —— 会话元数据（**不存全文**）
```sql
CREATE TABLE ai_conversations (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  title         TEXT,
  provider      TEXT NOT NULL,
  model         TEXT,
  mode          TEXT NOT NULL,        -- consult | workspace
  message_count INTEGER DEFAULT 0,    -- 仅计数，不存内容
  working_dir   TEXT,                 -- 关联工作目录（模式助手用）
  created_at    TEXT NOT NULL,
  updated_at    TEXT NOT NULL
);
```

> ⚠️ **红线**：聊天正文**不入库**。若需短期上下文，存内存 + 可选的用户显式开启的本地加密缓存，且必须在隐私设置中明示。

> **阶段9 补充（v11）**：
> - `permissions` 元素支持两种形态：**字符串**（无 scope）或 **对象** `{"permission": "net:http", "scope": ["api.open-meteo.com"]}`（带 scope，登记进 `plugin_permissions.scope`）。
> - 完整权限枚举（12 §A2）：`ui:widget` · `app:launch` · `window:read` · `clipboard:read` · `clipboard:write` · `ai:invoke` · `data:own` · `net:http`（scope=域名白名单）· `file:read` / `file:write`（scope=授权目录）· **`system:media`**（SMTC 读写，阶段9 为音乐插件新增——A2 原表未列媒体能力，不新增则"音乐"示例插件无权限可申）。
> - 未在枚举内的权限 → 安装直接拒绝（校验失败）；manifest 未声明的能力 → 运行时拦截（默认零权限，红线 V4）。

### 3.2.7 插件宿主桥协议（阶段9）
插件 JS 运行在 **UI webview 的沙箱 iframe**（`sandbox` 且无 `allow-same-origin`，opaque origin），
通过 `postMessage` 调用宿主能力；宿主（UI PluginHost）把**核心侧能力**转发给 core 权限网关：

```json
// iframe → 宿主
{ "__pwPlugin": true, "reqId": 1, "api": "system", "method": "mediaNow", "payload": {} }
// 宿主 → iframe（同 reqId 应答）
{ "__pwPlugin": true, "reqId": 1, "ok": true, "data": { ... } }
{ "__pwPlugin": true, "reqId": 2, "ok": false, "error": { "code": "permission_denied", "message": "..." } }
```

| api | 方法 | 所需权限 | 执行位置 |
|-----|------|----------|----------|
| `ui` | `notify(title, body)` | `ui:widget` | 宿主（应用内通知） |
| `system` | `appLaunch(nameOrId)` | `app:launch` | core 网关 → `app_manager` |
| `system` | `windowRead()` | `window:read` | core 网关 → `window_manager` |
| `system` | `mediaNow()` / `mediaControl(action)` | `system:media` | core 网关 → sidecar `/life/media*` |
| `data` | `get/set/delete/keys(key?)` | `data:own` | core 网关 → `plugins/<id>/data/<key>.json`（键名限 `[A-Za-z0-9_-]`，防路径穿越） |
| `ai` | `invoke(prompt, opts?)` | `ai:invoke` | core 网关校验权限+审计 → 宿主转 `ai_chat` command（AI 不走 HTTP 面，沿用阶段5 口径；对插件**恒为 consult 模式**，不注入用户数据） |
| `file` | `read/write(path, ...)` | `file:read` / `file:write` | core 网关 → 仅允许 `scope` 目录之内（前缀校验 + 规范化路径） |
| `net` | `http(url, opts?)` | `net:http` | core 网关 → scope 域名白名单校验；**仅实现 `http://`**（无 TLS crate，`https://` 明确不支持并返回 `https_unsupported`） |

> 每一次调用（含被拒绝的）都由 core 写 `plugin_audit`；越权时额外发布 `PLUGIN_PERMISSION_DENIED`。
> 运行时约定：iframe 加载 **10s** 内未报告 ready → 宿主标记"加载超时"（12 §A4）；
> iframe `window.onerror` → 宿主上报 core `plugin_crash` → `PLUGIN_ERROR` + 审计，插件标记"已停止"（可重启）。

### 3.2.6 AI 生成的路线（阶段6，`roadmap_generate` 的**输出契约**）
```json
{
  "goal": "学习计算机视觉并完成项目",
  "nodes": [
    { "title": "Python 基础", "order": 1, "estimated": "2周", "resources": ["官方教程", "基础练习题"] },
    { "title": "OpenCV",     "order": 2, "estimated": "3周", "resources": ["图像处理基础"] },
    { "title": "CNN",        "order": 3, "estimated": "3周" }
  ]
}
```
| 字段 | 必填 | 说明 |
|------|:----:|------|
| `nodes` | ✅ | 节点数组，**3~7 个** |
| `nodes[].title` | ✅ | 一句话说清"这一阶段学什么" |
| `nodes[].order` | ✅ | 从 1 开始，表示先后顺序 |
| `nodes[].estimated` | ⬜ | 预估时长，如 `"2周"` |
| `nodes[].resources` | ⬜ | 资料**方向**（非链接榜单），最多 3 条 |

> **这是"建议"而不是"事实"**：模型输出只用于**展示**（`advisory: true`）。
> 解析失败**必须降级**为文本展示 + 手动录入，**不得把 JSON 解析错误抛给用户**
> （09 §2）。解析由 `core/src/learning/roadmap.rs::parse` 负责，容忍：
> Markdown 围栏、前后废话、字段名变体、纯字符串节点、截断的 JSON；
> 降级时返回 `degraded: true` + `reason`，`nodes` 为空数组。
> 用户点"采纳"才走 `/api/v1/learning/goals/{id}/roadmap` 落库（红线 V3）。

## 3.3 Event Bus 事件表

统一 payload 外层：`{ "event": "MODE_CHANGED", "ts": "2026-09-12T17:30:00+08:00", "payload": { ... } }`

| 事件 | payload | 触发时机 |
|------|---------|----------|
| `MODE_CHANGED` | `{ modeId, name, apps }` | 模式切换成功 |
| `MODE_APPLY_PROGRESS` | `{ modeId, step, total, detail }` | 应用模式过程中的进度 |
| `MODE_APPLY_FAILED` | `{ modeId, step, reason, recoverable }` | 某一步失败（不中断整体） |
| `APP_REGISTERED` | `{ appId, name, path }` | 添加软件成功 |
| `APP_OPENED` | `{ appId, pid, hwnd }` | 进程启动成功 |
| `APP_CLOSED` | `{ appId, pid, exitCode }` | 进程退出 |
| `WINDOW_LAYOUT_APPLIED` | `{ layout, monitor, slots }` | 布局应用完成 |
| `WINDOW_LAYOUT_FAILED` | `{ layout, app, reason }` | 单个窗口定位失败 |
| `AI_REQUEST` | `{ conversationId, provider, mode }` | 发起 AI 请求 |
| `AI_STREAM_CHUNK` | `{ conversationId, delta }` | 流式返回片段 |
| `AI_RESPONSE` | `{ conversationId, tokens, durationMs }` | 请求结束（**不含正文**） |
| `LEARNING_PROGRESS_UPDATED` | `{ goalId, nodeId, status }` | 学习状态更新（**阶段6 起真正发出**；`status` 除节点状态枚举外还会出现 `roadmap_confirmed` / `deleted`，订阅方只应视为"该刷新了"的信号） |
| `LEARNING_REMINDER` | `{ goalId, title, idleDays }` | **阶段6** 目标长期未更新（默认 30 天，`learning.remind_after_days`）；同目标 7 天冷却 |
| `PROFILE_UPDATED` | `{ changed }` | **阶段7 起真正发出**：档案被用户确认/编辑后发布（`changed` ∈ basic\|skill\|project\|timeline\|batch\|suggestion 或被确认建议的 kind）。订阅方只应视为"该刷新了"的信号 |
| `PLUGIN_LOADED` | `{ pluginId, version }` | **阶段9 起真正发出**：插件启用（加载）成功 |
| `PLUGIN_ERROR` | `{ pluginId, reason }` | **阶段9 起真正发出**：插件崩溃/加载失败/加载超时（宿主上报或 core 判定） |
| `PLUGIN_PERMISSION_DENIED` | `{ pluginId, permission, scope }` | **阶段9 起真正发出**：越权访问被拦截（core 网关或宿主桥，权威判定在 core） |
| `CONFIG_CHANGED` | `{ key, oldValue, newValue }` | 配置项变更 |
| `DEVICE_METRICS_UPDATED` | `{ cpu, memUsed, memTotal }` | **阶段8 起真正发出**：设备指标采集循环每 tick（默认 2s，`device.metrics_interval_sec`）发布；GPU/温度 Windows 无免驱动通道，**不提供** |
| `LIFE_BREAK_REMIND` | `{ day, totalSeconds, thresholdHours }` | **阶段8** 今日累计使用时长跨过 `life.break_remind_hours` 阈值（0=关闭）；每天最多一条 |

## 3.4 本地 HTTP 接口（core ↔ python ↔ ui）

> **`pwplugin://` 自定义协议（阶段9）**：Tauri 注册 `pwplugin` scheme，UI 以
> `http://pwplugin.localhost/<pluginId>/<path>` 在沙箱 iframe 中加载插件文件。
> core 侧 `serve_file` 是唯一服务函数（canonicalize base + target、拒绝 `..`、
> 拒绝越出插件目录、5MB 上限），`pwplugin://` 协议 handler 与之共用；
> 插件静态文件**不设 HTTP REST 端点**（少一个攻击面），浏览器调试直接读盘。
> 文件服务本身无权限门槛（读静态 UI 资源），**能力调用**才走权限网关。
> `tauri.conf.json` 的 CSP 相应追加 `frame-src http://pwplugin.localhost`。

> ⚠️ **订正（阶段5）**：本表此前登记过 `POST /api/v1/ai/chat`，**该端点并不存在**。
> core 的 HTTP 面**刻意不暴露 AI**（`/api/v1` 与 `/internal` 都没有 `/ai/*`）：
> HTTP 面任何本地程序都能打，若 AI 走 HTTP，等于让任意进程借用户的模型额度与凭据发请求。
> 因此 **AI 一律只经 Tauri command**（下面 8 个），sidecar 的 `/ai/*` 只对 core 开放。
> 「UI 走 HTTP 兜底」这条规则在 AI 上是**例外**：浏览器环境下 AI 不可用，属预期。

## 3.5 契约变更流程

1. 先改本文件（表 / JSON / 事件 / 接口 / config 键）。
2. 升级 `schema_version`（在 `config` 表里）—— 同时改代码常量 `migrations::CONTRACT_SCHEMA_VERSION`。
3. 写 migration（若涉及表结构）。
4. 同步更新调用方。
5. 在本文件底部「变更记录」追加一行。

> **注 · 两个版本号不要混用（L-006）**
> - `config.schema_version` = **数据契约版本**（本文档管，当前 **v13**）；
> - `config.db.migration_version` = **迁移台账**（`core/migrations/` 管，记录已执行的 DDL 脚本序号）。
> - 不涉及表结构变更时**只升契约版本，不写 migration**。
