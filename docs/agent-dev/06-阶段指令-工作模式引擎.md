# 06 · 阶段指令 · 第三阶段：Workspace 工作模式引擎 ⭐ 核心

**优先级**：P0 · MVP · **★★★★★ 全项目最高**
**前置**：`04-基础框架`、`05-软件管理`、`07-窗口管理`
**目标一句话**：把"软件 + 文件 + 布局 + AI"打包成可一键进入的环境。

> ⚠️ 这是全项目唯一的创新点。这个做不好，其余模块做得再漂亮也没意义。
> 允许为了它砍掉别的功能，**不允许为了别的东西砍它**。

---

## 核心定义

**工作模式 ≠ 软件集合。**
工作模式 = **一套完整的数字工作环境快照**。

```
深度学习模式
├── 软件：VS Code、Chrome、PDF 阅读器、Terminal
├── 文件：学习资料目录、项目目录
├── AI  ：技术助手（带 file:read 权限）
└── 布局：
    ┌────────────┬────────────┐
    │  Chrome    │  VS Code   │
    ├────────────┼────────────┤
    │  PDF       │  Terminal  │
    └────────────┴────────────┘
              AI 侧栏
```

## 必须实现

### 1. 模式 CRUD
- 数据结构见 `03-数据契约与接口规范.md` 3.2.1。
- 创建流程（向导式，3 步）：
  1. **基本信息**：名称、图标、描述
  2. **选择软件**：从软件库多选 + 可设置启动参数
  3. **设置布局**：选模板 或 拖拽画布自定义 → 保存为 `layouts/<name>.json`
  4. **（附加）文件入口**：添加目录/文件（进入模式时打开）
  5. **（附加）AI 配置**：选 Provider、选提示词模板、设权限范围
- 支持从内置模板快速创建（`config/modes/` 提供 `学习模式`、`开发模式` 两个预设）。
- 支持复制模式、删除模式（软删除）。

### 2. ★ 模式应用（Apply）—— 本项目的灵魂

```
applyMode(modeId)
   │
   ├─ ① 校验     路径存在？软件已注册？布局文件可读？
   │             └─ 提前暴露问题，而不是执行到一半才报错
   │
   ├─ ② 启动软件  并发启动（不要串行等待！）
   │             └─ 每个 APP 独立超时 15s，失败记 MODE_APPLY_FAILED 继续
   │
   ├─ ③ 等待就绪  轮询直到拿到所有 pid 的 hwnd，或超时
   │             └─ 新启动的程序窗口出现需要时间，必须有等待
   │
   ├─ ④ 应用布局  调窗口管理，把每个窗口摆到指定位置
   │             └─ 见 07 阶段指令
   │
   ├─ ⑤ 打开文件  打开文件/目录入口（资源管理器或默认程序）
   │
   ├─ ⑥ 加载 AI   切换 AI 助手到该模式的配置与权限
   │
   └─ ⑦ 更新状态  写 use_count / last_used_at，发布 MODE_CHANGED
```

**关键工程要求**：

| 要求 | 说明 |
|------|------|
| **并发启动** | 步骤②必须并发，否则 4 个软件串行要等 20s+ |
| **进度可视** | 每步发布 `MODE_APPLY_PROGRESS`，UI 显示"正在启动 VS Code (2/4)" |
| **失败不中断** | 单个软件启动失败 → 记录 + 继续，最后汇总告知用户 |
| **幂等** | 已在运行的软件直接跳过启动，进入布局阶段 |
| **可取消** | 用户中途取消 → 停止后续步骤，已启动的不回滚（回滚更糟） |
| **可重试** | 失败的单项提供"重试"按钮 |
| **超时兜底** | 整体流程 45s 硬超时，避免卡死 |

**状态机**（必须显式建模，禁止用一堆 bool）：
```
Idle → Validating → Launching → WaitingReady → Arranging → OpeningFiles
     → LoadingAI → Done
                ↘ Failed(部分失败) → Done
任意状态 → Cancelled
```

### 3. 模式切换语义（重要设计决策）

当用户从模式 A 切到模式 B：

| 策略 | 行为 | 建议 |
|------|------|------|
| `additive`（默认） | 只启动 B 新增的，A 的软件保留 | ✅ 默认，符合直觉 |
| `exclusive`（可选） | 关闭 A 有但 B 没有的软件 | 需用户明确开启 |
| `ask` | 弹窗询问 | 首次切换时询问并记住选择 |

实现要求：切换前**必须**保存当前模式的运行快照，用于"回到上一个模式"。

### 4. 模式状态管理
- 全局唯一 `current_mode`，持久化到 `config`（重启后可恢复，但**默认不自动重新应用**，只在 UI 上显示"上次使用的模式"并提供一键恢复）。
- 提供 `autoApply`：用户可勾选"应用启动时自动进入此模式"。
- 模式运行时记录：哪些软件是模式拉起的、哪些是用户自己开的（模式只管理自己拉起的）。

### 5. UI
- **模式卡片**：图标 + 名称 + 软件数 + 使用次数；hover 显示预览（软件图标 + 布局缩略图）。
- **一键进入按钮**：大而显眼，位于卡片主区域。
- **应用进度面板**：步骤清单（每步 ✅/⏳/❌）+ 失败项的"重试"。
- **模式编辑器**：拖拽画布（网格吸附），支持四分屏/左右/上下/三分 等模板。
- **模式栏**：常驻顶部或侧边，显示当前模式，可快速切换。

## 技术要点

### 启动等待的正确做法
```python
# 伪代码：等待窗口就绪
def wait_ready(pids, timeout=20):
    deadline = now() + timeout
    while now() < deadline:
        ready = {pid: find_main_hwnd(pid) for pid in pids}
        if all(ready.values()):
            return ready
        sleep(0.3)
    return partial_ready  # 返回已就绪的，未就绪的标记失败
```
- 不要用固定 `sleep(5)` 糊过去——慢机器会失败，快机器浪费时间。
- 有些程序启动会先出 splash 窗口，需要过滤（按窗口尺寸/类名/可见性过滤），等真正的主窗口。

### 配置文件双写问题
模式数据同时存在数据库和 `layouts/*.json`。规则：
- **数据库是唯一真相**，布局 JSON 是导出/导入格式。
- 用户编辑布局 → 写数据库 `layouts` 表 → 同时导出 JSON 到 `config/layouts/` 供版本管理与分享。
- 禁止只改 JSON 不同步数据库。

### 内置预设（必须在 `config/modes/` 提供）
```json
// 学习模式
{
  "name": "学习模式",
  "apps": ["Chrome", "PDF阅读器", "笔记软件"],
  "layout": "study.json",
  "aiProfile": { "provider": "default", "systemPromptKey": "study_assistant" }
}
```
```json
// 开发模式
{
  "name": "开发模式",
  "apps": ["VS Code", "Chrome", "Terminal"],
  "openTargets": [{ "path": "", "label": "当前项目", "type": "folder" }],
  "layout": "coding.json",
  "aiProfile": { "provider": "default", "systemPromptKey": "dev_assistant" }
}
```

## 验收标准

| # | 验收项 | 方法 |
|---|--------|------|
| 1 | 创建模式 | 通过向导建一个含 4 个软件的模式，重启后仍在 |
| 2 | **一键进入** | 点"进入"→ 4 个软件全部启动 + 窗口排列正确，全程 < 20s |
| 3 | 进度可见 | 过程中能看到"正在启动 X (2/4)" |
| 4 | 容错 | 故意把一个软件路径改错 → 其余 3 个正常启动，失败的项有提示与重试 |
| 5 | 幂等 | 连续点两次"进入"不会重复拉起程序 |
| 6 | 可取消 | 启动过程中点取消 → 后续步骤停止，UI 状态正确 |
| 7 | 切换 | 从模式 A 切到 B（additive）→ A 的软件不被关闭，B 的新增被拉起 |
| 8 | 布局持久化 | 改布局 → 保存 → 再次进入模式，窗口按新布局排列 |
| 9 | 状态显示 | 顶部模式栏正确显示当前模式 |
| 10 | 恢复 | 重启应用 → 显示"上次使用：开发模式"，一键恢复可用 |

## 禁止事项

- ❌ 不要串行启动软件
- ❌ 不要用固定 sleep 代替窗口就绪检测
- ❌ 不要在某个软件失败时中断整个流程
- ❌ 不要用一堆布尔变量表达流程状态（必须显式状态机）
- ❌ 不要让模式定义里出现硬编码路径（路径必须来自软件注册表或用户选择）
