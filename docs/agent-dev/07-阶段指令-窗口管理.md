# 07 · 阶段指令 · 第四阶段：窗口管理系统

**优先级**：P0 · MVP
**前置**：`04-基础框架`（需先定 ADR-001）
**目标一句话**：让系统自动把窗口摆到该在的位置，替代 Alt+Tab。

**验收一句话**：点一个模式，多个软件窗口在 3s 内自动排列成四宫格。

---

## 目标

把"用户手动拖窗口"这件事彻底消灭。

## 必须实现的能力

### 1. 窗口查找（Find）
- 输入：`pid` 或 窗口标题关键词
- 输出：`{ hwnd, title, className, rect, monitor, isVisible }`
- 必须过滤掉非主窗口：不可见的、0 尺寸的、工具窗口（`WS_EX_TOOLWINDOW`）、splash 窗口。
- 一个进程可能有多个窗口 → 取面积最大的可见窗口作为主窗口（可配置）。

**Windows API 参考**：
```
EnumWindows            → 遍历所有顶层窗口
IsWindowVisible        → 过滤不可见
GetWindowRect          → 取位置尺寸
GetWindowThreadProcessId → hwnd → pid
GetClassName / GetWindowText → 识别窗口
GetWindowLongPtr(GWL_EXSTYLE) → 过滤 WS_EX_TOOLWINDOW
```
Python 侧简化版：
```python
import win32gui, win32process
def find_main_hwnd(pid):
    result = []
    def cb(hwnd, _):
        if not win32gui.IsWindowVisible(hwnd):
            return True
        _, wpid = win32process.GetWindowThreadProcessId(hwnd)
        if wpid != pid:
            return True
        l, t, r, b = win32gui.GetWindowRect(hwnd)
        if (r - l) * (b - t) <= 0:
            return True
        result.append((hwnd, (r - l) * (b - t)))
    win32gui.EnumWindows(cb, None)
    return max(result, key=lambda x: x[1])[0] if result else None
```

### 2. 窗口定位（Set）
- 输入：`hwnd`, 目标矩形（像素）, 是否激活, 是否置顶, 是否最大化
- 输出：成功/失败

**关键：先取消最大化再移动**（否则 `SetWindowPos` 无效）：
```
if IsZoomed(hwnd): ShowWindow(hwnd, SW_RESTORE)
SetWindowPos(hwnd, HWND_TOP, x, y, w, h, SWP_NOZORDER | SWP_SHOWWINDOW)
ShowWindow(hwnd, SW_RESTORE)
```
Python 侧：
```python
win32gui.ShowWindow(hwnd, win32con.SW_RESTORE)
win32gui.SetWindowPos(hwnd, win32con.HWND_TOP, x, y, w, h,
                      win32con.SWP_NOZORDER | win32con.SWP_SHOWWINDOW)
```

### 3. 激活窗口（Foreground）
Windows 有前台锁定限制，直接 `SetForegroundWindow` 常失败。可靠方案：
```
AttachThreadInput(当前线程, 目标窗口线程, True)
BringWindowToTop(hwnd)
SetForegroundWindow(hwnd)
AttachThreadInput(当前线程, 目标窗口线程, False)
```
- 激活顺序：按布局的 `z` 值，**从大到小倒序激活**（先激活最大的，最后激活要显示在最上层的）——或者反向，取决于最终层叠需求，需实测确定并在 README 记录。
- 有最小化状态时先 `ShowWindow(SW_RESTORE)`。

### 4. 布局计算（归一化 → 像素）
- 输入：`layout.slots`（0~1 归一化坐标）+ `monitor` 索引
- 输出：每个槽位的像素矩形

```
工作区 = 显示器工作区（不含任务栏）  ← 用 SPI_GETWORKAREA 或 monitor.work_area
若 aiSidebar.enabled:
    可用宽度 = 工作区宽 - aiSidebar.width * 工作区宽
    再把每个 slot 的归一化 x 映射到可用宽度
像素 x = workArea.x + round(slot.x * availableW / 剩余归一化总宽)
```

**必须处理**：
- **DPI 缩放**：应用必须声明 per-monitor DPI aware（`SetProcessDpiAwarenessContext(PER_MONITOR_AWARE_V2)`），否则在高分屏上坐标全错。
- **多显示器**：`monitor` 索引 → 取对应显示器的 work area；显示器不存在时降级到主显示器并警告。
- **分辨率变化**：监听显示设置变化，提示用户重新应用模式。

### 5. 布局模板（内置）
| 名称 | 说明 |
|------|------|
| `full` | 单窗口全屏 |
| `split-v` | 左右各半 |
| `split-h` | 上下各半 |
| `quad` | 四宫格 |
| `main-side` | 左侧 2/3 主窗口 + 右侧 1/3 副窗口 |
| `coding.json` | 左 VS Code，右上 Chrome，右下 Terminal，右侧 AI 侧栏 |
| `study.json` | 左 Chrome，右上 PDF，右下笔记，右侧 AI 侧栏 |

### 6. UI
- 布局编辑器：网格画布，拖拽划分区域，为每个区域指定应用，实时预览比例。
- 显示器选择（多屏时）。
- "重新应用布局"按钮（窗口被用户手动挪乱后一键复位）。

## 工程要求

| 要求 | 说明 |
|------|------|
| 单窗口失败不阻塞 | 发 `WINDOW_LAYOUT_FAILED`，继续处理其他窗口 |
| 自动重试 | 定位失败重试 2 次，间隔 500ms（窗口可能还没完全初始化） |
| 超时 | 单个窗口操作 5s |
| 分步延时 | 连续移动多个窗口时，每次操作间隔 50~100ms，避免被系统丢弃 |
| 可测试 | 布局计算（归一化→像素）必须是纯函数，可脱离系统单测 |

## 验收标准

| # | 验收项 | 方法 |
|---|--------|------|
| 1 | 查找窗口 | 给定 pid 能返回正确 hwnd；无窗口时返回 null 不报错 |
| 2 | 定位窗口 | 目标窗口精确移动到指定像素位置（±2px） |
| 3 | 四宫格 | 4 个软件自动排列成四宫格，无重叠 |
| 4 | 最大化恢复 | 目标是最大化状态的应用能被正确取消最大化再定位 |
| 5 | 激活 | 指定窗口被激活并置前 |
| 6 | AI 侧栏留位 | 启用侧栏时，窗口不覆盖右侧 AI 区域 |
| 7 | 多显示器 | 在第二显示器上应用布局正确 |
| 8 | 高分屏 | 150% 缩放下布局比例仍然正确 |
| 9 | 容错 | 某个应用未启动 → 该槽位跳过，其余窗口正常排列 |
| 10 | 纯函数测试 | 归一化坐标换算有单元测试用例（含多屏 + 侧栏 + DPI） |

## 禁止事项

- ❌ 不要把像素坐标写死在布局文件里（必须用归一化坐标）
- ❌ 不要忽略 DPI 感知声明
- ❌ 不要在窗口还没创建完成时立刻定位（先等就绪）
- ❌ 不要用 `SetForegroundWindow` 硬冲而不处理前台锁定
