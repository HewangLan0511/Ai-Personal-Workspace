# 08 · 阶段指令 · 第五阶段：AI 助手系统

**优先级**：P0 · MVP
**前置**：`04-基础框架`
**目标一句话**：把 AI 变成工作环境的一部分，而不是另一个网页。

**验收一句话**：侧栏能对话、能切模型、工作助手模式能读到当前项目和模式信息。

---

## 核心设计：双模式（不可混为一谈）

### 模式一：AI 咨询模式（Consult）
- 独立聊天，**不访问任何用户数据**
- 类似普通 AI 聊天工具
- 无文件权限、无软件权限
- 会话内容**不落库**（只存元数据）

### 模式二：AI 工作助手模式（Workspace Assistant）
- 拥有权限，可访问：
  - 工作模式信息（当前模式、包含哪些软件）
  - 项目入口（用户显式添加的目录）
  - 文件（限授权目录内）
  - 学习状态（目标与进度）
  - 个人档案（技能/项目）
- 可执行：
  - 文件整理（在授权目录内）
  - 项目辅助（读代码、生成文档）
  - 工作建议（基于当前模式给出下一步）

**权限边界必须在 UI 上显式展示**：侧栏顶部常驻一个"🔓 已授权：项目目录、学习状态"的提示，可点击查看/撤销。

---

## 必须实现

### 1. AI Provider 抽象层 ★
**禁止任何业务代码直接发某个模型的 HTTP 请求。** 统一接口：

```python
class AIProvider(Protocol):
    name: str
    async def chat(self, messages: list[Message], *, model: str = None,
                   tools: list[Tool] = None, stream: bool = False,
                   timeout: int = 60) -> AsyncIterator[Chunk] | Response: ...
    async def list_models(self) -> list[str]: ...
    async def health(self) -> bool: ...
```

**必须支持的 Provider**：

| Provider | 接入方式 | 备注 |
|----------|----------|------|
| OpenAI 兼容 | HTTP `/v1/chat/completions` | 覆盖 OpenAI、DeepSeek、通义、Kimi 等所有兼容接口 |
| DeepSeek | 同上（OpenAI 兼容） | base_url + api_key |
| Ollama | `http://localhost:11434` | 本地，无需 key |
| LM Studio | `http://localhost:1234/v1` | 本地，OpenAI 兼容 |
| 网页 AI | 内嵌 WebView | 优点：无需 API 费用。需明确告知用户：这是浏览器模式，不参与工具调用 |
| 用户 Agent | HTTP / WebSocket | 见 3.2.5，支持自定义 Agent 接入 |

**配置项**（每个 Provider）：`api_base`、`api_key_ref`（凭据库引用，**不是明文 key**）、`model`、`temperature`、`max_tokens`、`timeout`。

### 2. 凭据安全
- API Key 存 **Windows Credential Manager**（`keyring` 库 / Tauri stronghold）。
- 数据库只存引用名，如 `credential_ref = "pw/deepseek/default"`。
- 设置页输入 key 后**立即写入凭据库**，界面只显示 `sk-****abcd`。

### 3. 流式输出
- 必须支持流式（用户等 20s 看空白屏是不可接受的）。
- 事件序列：`AI_REQUEST` → 多个 `AI_STREAM_CHUNK` → `AI_RESPONSE`。
- 前端用 SSE 或 WebSocket 接收增量。
- 支持中断（用户点停止 → 取消请求）。

### 4. 提示词模板集中管理
`ai/prompt/` 下集中存放，禁止散落在代码里：
```
ai/prompt/
├── consult_default.md        # 咨询模式默认
├── study_assistant.md        # 学习助手
├── dev_assistant.md          # 开发助手
├── profile_suggest.md        # 档案更新建议（V2）
└── roadmap_generate.md       # 学习路线生成（V2）
```
模板变量用 `{{变量名}}`，例如 `{{current_mode}}`、`{{recent_projects}}`、`{{learning_goals}}`。

### 5. AI 侧栏（UI）
- 位置：右侧可收起侧栏，宽度可拖拽，宽度持久化。
- 顶部：模式切换（咨询 / 工作助手）+ 当前 Provider/模型选择器 + 权限提示。
- 中部：对话流（支持 Markdown 渲染、代码高亮、复制）。
- 底部：输入框（支持多行、`Ctrl+Enter` 发送、`Shift+Enter` 换行）。
- 工作助手模式下：显示"当前上下文"标签（如 `#开发模式` `#项目:my-app`）。

### 6. 上下文注入（工作助手模式的关键）
进入某个工作模式时，自动注入该模式的上下文：
```
[系统] 当前工作模式：开发模式
       已打开软件：VS Code, Chrome, Terminal
       项目目录：D:/projects/my-app
       最近学习目标：掌握 Rust 异步
[提示] 你应以开发助手身份回答，必要时可建议如何利用当前环境。
```
- 上下文**按需注入**，不要无脑塞全部档案（会浪费 token 且降低质量）。
- 提供开关让用户控制哪些上下文参与。

### 7. 失败与降级
| 情况 | 处理 |
|------|------|
| API Key 未配置 | 提示引导去设置，不在 UI 里显示报错堆栈 |
| 网络不可达 | 明确提示，并提供切换到本地模型（Ollama/LM Studio）的快捷入口 |
| 本地模型未启动 | 提示"检测到 Ollama 未运行，是否启动？" |
| 超时 | 按 Provider 配置超时，可重试 |
| 限流 (429) | 退避重试 + 提示 |

## 验收标准

| # | 验收项 | 方法 |
|---|--------|------|
| 1 | 基础对话 | 配置一个云端 API，能正常问答 |
| 2 | 流式 | 回答是逐字出现的，不是等了 10s 一次性蹦出来 |
| 3 | 中断 | 生成中点停止 → 立即停止输出 |
| 4 | 多 Provider | 切到 Ollama（本地）能正常对话，切换不需要重启应用 |
| 5 | 模型列表 | 能在 UI 里选择模型（从 Provider 拉取或手填） |
| 6 | 凭据安全 | 数据库里搜不到明文 key；keyring 中存在 |
| 7 | 双模式隔离 | 咨询模式提问"我的项目是什么" → 不应获得任何真实项目信息 |
| 8 | 上下文注入 | 工作助手模式提问"我现在该做什么" → 回答能引用当前模式与项目 |
| 9 | 侧栏持久化 | 侧栏宽度、位置、上次选择的模型在重启后保持 |
| 10 | 降级 | 断网时给出可读提示，应用不崩溃 |

## 禁止事项

- ❌ 不要在业务代码里硬编码模型名或 API 地址
- ❌ 不要把 API Key 明文存 SQLite 或写进代码
- ❌ 不要把聊天全文落库
- ❌ 不要让咨询模式能读到用户数据（这是隐私红线）
- ❌ 不要做"无流式"的实现（体验不可接受）
