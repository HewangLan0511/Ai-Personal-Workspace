# 10 · 阶段指令 · 第七阶段：个人数字档案

**优先级**：V2
**前置**：`05-软件管理`、`09-学习成长`
**定位一句话**：记录 **"我是谁，我正在成为谁。"**

---

## 核心流程（不可绕过）

```
系统发现变化
    ↓
AI 生成建议
    ↓
★ 用户确认 ★
    ↓
写入档案
```

**用户确认是硬关口。** 档案是用户的自我认知记录，AI 不能代表用户改它。

---

## 必须实现

### 1. 基础信息
- 名称、方向、兴趣标签、一句话签名。
- 表：`profile_basic`。
- 首次使用引导填写（3 个字段，别搞长表单）。

### 2. 技能树
- 表：`profile_skills`，字段 `name` / `level(0-100)` / `source` / `confirmed`。
- 可视化：横向进度条或雷达图。
```
Python          ███████  70
OpenCV          █████    50
Deep Learning   ███      30
```
- **等级怎么来的**：用户手填，或 AI 根据项目/学习数据建议（`source = ai_suggested`, `confirmed = 0`，需用户点确认才生效）。
- 支持技能分类（编程语言 / 框架 / 工具 / 领域知识）。

### 3. 项目经历
- 表：`profile_projects`。
- 数据来源：
  1. 用户手动添加
  2. 从"项目管理"模块同步（用户确认过的项目）
  3. AI 从项目目录（如 git 仓库、README）推断 → **必须用户确认**
- 每条项目记录要有 `confirmed` 标记，未确认的不计入档案展示。

### 4. 成长时间线
- 表：`profile_timeline`。
- 记录重要节点：技能突破、项目完成、学习里程碑、证书等。
- 可视化：竖向时间轴，按年/月分组。
- 自动采集候选事件（如"学习目标 X 已完成"）→ 生成待确认条目 → 用户确认后入时间线。

### 5. 动态更新机制
**触发点**（系统"发现变化"）：
| 变化源 | 建议内容 |
|--------|----------|
| 学习目标完成 | 建议加入时间线 + 提升相关技能等级 |
| 项目状态变为 done | 建议加入项目经历 + 时间线 |
| 某软件使用频率长期极高 | 建议加入技能（如 VS Code 高频 → 提示"是否将 开发工具 加入技能？"） |
| 新增项目目录 | 建议添加项目 |

**实现要求**：
- 建议以**待确认队列**形式存在（`pending_suggestions`），不做弹窗轰炸。
- 在档案页顶部显示"N 条待确认的档案变化"。
- 用户可以：逐条确认 / 批量确认 / 忽略 / 永久拒绝某类建议。
- 确认后才写正式表，同时发布 `PROFILE_UPDATED`。

### 6. 个人主页（档案展示页）
- 顶部：基础信息 + 一句话签名
- 中部左：技能树；中部右：项目经历
- 底部：成长时间线
- **支持导出**：Markdown / PDF（用于分享或写简历）——这是很实用的小功能，优先做 Markdown。

### 7. 隐私要求
- 档案是敏感数据，全部本地存储。
- 只有"AI 工作助手模式"在用户授权下才能读取档案片段。
- 导出文件时明确告知导出内容。

---

## 验收标准

| # | 验收项 | 方法 |
|---|--------|------|
| 1 | 基础信息 | 填写后展示在主页，重启保持 |
| 2 | 技能树 | 添加技能、调等级，可视化同步更新 |
| 3 | AI 建议不自动生效 | 让系统发现变化 → 出现待确认条目，档案数据未变 |
| 4 | 确认后生效 | 点确认 → 数据写入，时间线/技能出现新条目 |
| 5 | 时间线 | 按时间倒序正确分组展示 |
| 6 | 项目同步 | 项目管理里完成一个项目 → 出现"是否加入档案"建议 |
| 7 | 权限 | 咨询模式的 AI 问"我的技能有哪些" → 不应知道答案 |
| 8 | 导出 | 导出 Markdown，内容完整、格式可读 |

## 禁止事项

- ❌ 不允许 AI 建议直接写入档案（必须走确认队列）
- ❌ 不要把档案数据发送给未授权的 Provider
- ❌ 不要做无法撤销的档案修改（保留修改历史或至少可删除）
- ❌ 不要在主页堆砌所有数据（技能树超过 20 项要分组折叠）
