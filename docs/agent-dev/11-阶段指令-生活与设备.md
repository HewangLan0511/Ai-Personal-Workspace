# 11 · 阶段指令 · 第八阶段：生活中心 + 设备中心

**优先级**：V3（生活）/ V3（设备）
**前置**：`04-基础框架`
**实现形式**：**以插件形式实现**（见 `12-阶段指令-插件与小组件.md`），核心只提供宿主能力。

> 本阶段是"插件系统的第一批真实用户"。做这些的同时也在验证插件架构是否真的好用。
> 如果做生活中心时发现必须改核心代码，说明插件架构设计失败了——回头改架构，不要打补丁。

---

## A. 生活中心

### A1. 天气
- 通过天气 API 获取（默认提供一个免费方案，允许用户换 API Key）。
- 展示：当前温度、天气状况、未来 3 天简况。
- 缓存 30 分钟，避免频繁请求。
- 定位：用户手动设置城市（**不要默认获取系统定位**，隐私优先）。

### A2. 音乐（轻量组件）
- 展示：当前歌曲名、歌手、封面、播放进度。
- 控制：播放/暂停/上一首/下一首（可选，能拿到会话就做）。
- 技术：Windows **SMTC**（`GlobalSystemMediaTransportControlsSessionManager`），读系统当前媒体会话，**不需要接入具体播放器**。
  ```python
  # winsdk / winrt
  from winsdk.windows.media.control import GlobalSystemMediaTransportControlsSessionManager
  ```
- 不保存播放历史（数据轻量化）。

### A3. 社交中心（只做概览）
- 定位：**消息总览**，不是聊天客户端。
- 用户显式选择接入哪些服务。
- **红线**：
  - ❌ 不保存聊天内容
  - ❌ 不自动发送消息
  - ❌ 不做无授权的爬取
- 展示：未读数量、消息来源摘要、跳转到原应用。

### A4. 健康生活
- 记录屏幕使用时间。
- 数据来源：前台窗口采样（每 30s 记录一次当前前台进程，累计到 `usage_stats`）。
- 展示：
  - 今日总使用时长
  - 各软件使用时长排行
  - 周趋势图
- 采样数据只存聚合结果（按天+应用），不存时间点明细（数据轻量化）。
- 可选：连续使用超过 N 小时提醒休息（默认关闭）。

## B. 设备中心

### B1. 第一阶段范围
**只管理电脑**（手机/平板/其他设备放后续版本）。

### B2. 硬件监控
- CPU 使用率、GPU 使用率、内存占用、磁盘占用、温度（能拿到就拿）。
- 技术：`psutil`（CPU/内存/磁盘）+ WMI / Performance Counter（GPU、温度）。
```
CPU      ██████░░░░  42%
GPU      ███░░░░░░░  18%
内存     12.4 / 32 GB
```
- 刷新频率：默认 2s（可配置），发 `DEVICE_METRICS_UPDATED`。
- 历史曲线：只保留最近 5 分钟（内存环形缓冲，**不落库**）。

### B3. 软件状态
- 当前运行的程序列表（进程名、PID、内存占用、CPU 占用）。
- 支持结束进程（**必须有二次确认**，这是危险操作）。
- 支持从运行列表快速"添加到软件库"（联动 05 阶段）。

### B4. 与工作模式的联动（亮点）
- 进入模式时，设备中心显示该模式各软件的启动耗时统计。
- "模式健康度"：某个软件启动经常超时 → 在模式卡片上提示。

## 验收标准

| # | 验收项 | 方法 |
|---|--------|------|
| 1 | 天气 | 设置城市后正确显示当前天气，缓存生效 |
| 2 | 音乐 | 打开一个播放器播放音乐 → 组件显示歌曲信息 |
| 3 | 消息概览 | 接入一个服务后显示未读数（无内容落库） |
| 4 | 使用时间 | 记录前台应用时长，能查看今日排行 |
| 5 | 隐私 | 数据库里搜不到任何聊天内容 |
| 6 | 设备指标 | CPU/内存数据与实际系统工具接近 |
| 7 | 进程管理 | 能列出运行程序；结束进程有二次确认 |
| 8 | 插件形态 | 以上功能**全部以插件形式实现**，核心代码零改动 |

## 禁止事项

- ❌ 不要默认获取系统定位
- ❌ 不要保存聊天内容
- ❌ 不要在无确认的情况下结束进程
- ❌ 不要高频轮询（CPU 采集 < 1s 间隔会明显影响性能）
- ❌ 不要为了这些功能修改核心代码
