# 12 · 阶段指令 · 第九阶段：插件系统 + 桌面小组件 + 外部 Agent 接入

**优先级**：V3
**前置**：MVP 全部完成
**目标一句话**：让系统可扩展，并且**新增功能不需要改核心代码**。

---

## 设计目标

Personal Workspace 的第一天就要为"无限扩展"留路。插件系统是这条路。

**判定标准**：写一个新插件（比如"番茄钟"），只需要在 `plugins/` 下加一个目录 + 一个 manifest，**零核心代码改动**即能跑起来。

---

## A. 插件系统

### A1. 插件结构（强制）
```
plugins/
└── com.example.music/
    ├── manifest.json        # 元信息 + 权限声明（见 3.2.4）
    ├── main/                # 逻辑入口
    │   └── index.js
    ├── ui/                  # 界面
    │   └── index.html
    └── data/                # 插件私有数据（宿主隔离）
```

### A2. 四类 API（宿主提供给插件）
| API | 能力 | 权限名 |
|-----|------|--------|
| **UI API** | 创建界面、注册 Widget、注册路由、弹通知 | `ui:widget` |
| **System API** | 启动软件、读窗口信息、读写剪贴板 | `app:launch` `window:read` `clipboard:read/write` |
| **AI API** | 调用模型（走统一 Provider 抽象） | `ai:invoke` |
| **Data API** | 读写插件自己的数据（隔离存储空间） | `data:own` |
| **Network** | 发起 HTTP 请求 | `net:http`（需声明域名白名单） |
| **File** | 读写文件（限用户授权目录） | `file:read` / `file:write`（带 scope） |

### A3. 权限管理（类似浏览器插件）
- 插件安装时**展示权限清单**，用户必须明确同意。
- **默认零权限**，未声明的能力直接拦截。
- 越权访问 → 发 `PLUGIN_PERMISSION_DENIED`，记录审计日志，必要时禁用插件。
- 权限可在设置页随时撤销（撤销后插件自动禁用）。
- 权限数据：`plugin_permissions` 表。

### A4. 插件生命周期
```
发现 → 校验（manifest 合法性 + 版本兼容）→ 安装 → 用户授权
     → 启用（加载）→ 运行 → 禁用 → 卸载（清理 data/）
```
- 插件崩溃不能影响主程序 → 崩溃后发 `PLUGIN_ERROR`，UI 标记"已停止"，可重启。
- 加载超时（10s）视为失败。
- 提供插件市场/本地安装两种方式（V3 只做本地目录安装 + 手动导入 zip）。

### A5. UI
- 插件管理页：已安装列表（启用开关、权限查看、卸载、打开插件页面）
- 安装流程：选择目录/zip → 展示 manifest 与权限 → 用户确认 → 安装
- 插件 Widget 可添加到 Dashboard（受 Widget 系统管理）

## B. 桌面小组件

### B1. 定位
后台常驻的轻量信息展示，无需打开主窗口也能看到关键状态。

### B2. 功能
- 独立的透明/半透明小窗口，**始终置顶**、无边框、可拖动。
- 显示内容（可多选组合）：
  - 时间
  - 天气
  - 下一课程 / 下一个日程（需日程数据源，可用学习目标里程碑代替）
  - CPU / 内存
  - 当前工作模式
  - 当前播放音乐
- 支持：
  - 拖动定位（位置持久化）
  - 缩放（0.8x ~ 2x）
  - 自定义显示哪些项、透明度、主题
  - 开机自启（可选）

### B3. 技术要点
- 用**独立的 Tauri 窗口**实现（`transparent: true`, `decorations: false`, `alwaysOnTop: true`, `skipTaskbar: true`）。
- **不要**用主窗口套一层假的小组件（会随之最小化）。
- 拖动用 CSS `-webkit-app-region: drag`。
- 性能：CPU 占用必须 < 1%，刷新间隔 ≥ 1s。

## C. 外部 Agent 接入（设计目标 3 的落地）

### C1. 统一协议
允许用户把自己写的 Agent 挂进来。配置见 `03-数据契约与接口规范.md` 3.2.5。

### C2. 通信
- **HTTP**：`POST {url}/invoke`，body `{ action, payload, context }`
- **WebSocket**：双向流式，用于实时协作
- 支持健康检查（`/health`）、超时、重试

### C3. 能力范围（由权限决定）
外部 Agent 可被授予：
- 读取工作模式与项目入口
- 读取档案（需显式授权）
- 触发模式切换（需显式授权，且**每次都要二次确认**）
- 调用 AI Provider

### C4. 安全红线
- 外部 Agent 默认无任何写权限。
- 涉及"执行动作"的（切模式、启软件、写文件）必须**逐次确认**或用户显式开启"信任模式"。
- 所有调用记审计日志（谁、何时、做了什么）。

## 验收标准（插件架构真正的考试）

| # | 验收项 | 方法 |
|---|--------|------|
| 1 | **零改动扩展** ★ | 新写一个"番茄钟"插件，不修改任何 core 代码就能在 Dashboard 显示并工作 |
| 2 | 权限拦截 | 插件申请 `file:read` 但未授权 → 读取被拦截，发权限拒绝事件 |
| 3 | 权限展示 | 安装时能看到完整的权限清单 |
| 4 | 崩溃隔离 | 让插件抛异常 → 主程序正常运行，插件标记为已停止 |
| 5 | 卸载清理 | 卸载插件后 `plugins/<id>/data` 被清理，数据库无残留 |
| 6 | 加载超时 | 构造一个卡死的插件 → 10s 后被标记失败，不影响启动 |
| 7 | 小组件独立 | 最小化主窗口 → 小组件仍显示且置顶 |
| 8 | 小组件性能 | CPU 占用 < 1% |
| 9 | 小组件持久化 | 拖动位置与缩放比例重启后保持 |
| 10 | 外部 Agent | 本地起一个 mock Agent → 能通信，无权限时调用被拒 |
| 11 | 生活中心迁移 | 天气/音乐等插件在新架构下正常运行 |

## 禁止事项

- ❌ 不要让插件直接访问 SQLite（必须走 Data API）
- ❌ 不要让插件阻塞主线程
- ❌ 不要给插件默认权限
- ❌ 不要为了让某个插件跑起来就在核心里加特判（`if plugin_id == "xxx"`）——这是架构失败的信号
- ❌ 不要让外部 Agent 无确认执行破坏性动作
