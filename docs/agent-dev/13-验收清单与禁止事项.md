# 13 · 全局验收清单与禁止事项

> 每个阶段交付前、以及每次合并到主分支前，对照本文件自检。

## 一、阶段门禁（每次交付必查）

### 1.1 代码质量
- [ ] `cargo check` / `cargo clippy` 无 error
- [ ] `tsc --noEmit` 无 error
- [ ] `npm run build` 成功
- [ ] 无 `unwrap()` 直穿到 UI
- [ ] 无 `print` / `console.log` / `debugger` 残留
- [ ] 无 `TODO` / `FIXME` 留在主执行路径上
- [ ] 无注释掉的死代码

### 1.2 架构合规
- [ ] `core/` 未依赖 `modules/` / `plugins/` / `ui/`
- [ ] `ui/` 未直接读写 SQLite
- [ ] `plugins/` 未直接访问数据库
- [ ] 数据库写入只发生在 core
- [ ] 跨模块通信走 Event Bus，无直接函数耦合
- [ ] 事件名/表名/权限名走常量，无散落魔法字符串

### 1.3 数据契约
- [ ] 新增的表/JSON/事件/接口已登记到 `03-数据契约与接口规范.md`
- [ ] 表结构变更提供了 migration 脚本（只增不改）
- [ ] `schema_version` 已更新
- [ ] 旧版本数据可升级（写了升级路径，实测过）

### 1.4 用户体验
- [ ] 所有失败路径有用户可读的提示（不是错误码）
- [ ] 所有异步操作有 loading 状态
- [ ] 所有长耗时操作可取消或有进度
- [ ] 所有设置项重启后保持
- [ ] 空状态有引导（不是一片空白）

### 1.5 安全与隐私
- [ ] 无明文密钥进数据库 / 代码 / git
- [ ] 插件权限默认拒绝
- [ ] 无未经确认的破坏性操作（结束进程/删除文件）
- [ ] 聊天内容未落库
- [ ] 无遥测回传（除非用户主动开启）

### 1.6 文档
- [ ] 新模块有 README（用途/接口/依赖/验收步骤）
- [ ] 手动验收步骤可被他人复现
- [ ] 未解决项与已知限制已列出

## 二、MVP 总体验收（照着实操一遍）

按顺序执行，任一步失败即为 MVP 未达标：

1. **启动**：打开应用 → 3s 内看到 Dashboard，无白屏
2. **加软件**：添加 VS Code、Chrome、Terminal、PDF 阅读器到软件库，图标正确
3. **建模式**：创建"深度学习模式"，包含这 4 个软件，设置四宫格布局 + AI 侧栏
4. **★ 一键进入**：点击"进入模式" → 20s 内 4 个软件全部启动，窗口自动排列成四宫格，AI 侧栏就位
5. **容错**：把其中一个软件路径改错 → 再进入 → 其余 3 个正常，失败的项有提示且可重试
6. **切换**：创建"开发模式"（3 个软件）→ 从深度学习模式切过去 → 行为符合 additive 策略
7. **AI**：侧栏里用工作助手模式问"我现在该专注什么" → 回答引用当前模式与项目
8. **隐私**：切到咨询模式，问"我的项目是什么" → 不应获得真实信息
9. **持久化**：重启应用 → 软件库、模式、布局、设置、AI 配置全部保持
10. **离线**：断网 → 除 AI 外全部功能可用

**通过标准：10 项全部通过。** 第 4 项是核心，若它不通过，其余通过也没有意义。

## 三、禁止事项总表（红线）

### 架构红线
| ❌ 禁止 | ✅ 应该 |
|---------|---------|
| 把所有功能写进主程序 | Core + Modules + Plugins 分层 |
| core 里 import 具体插件 | 通过宿主接口加载 |
| UI 直接读写数据库 | 走 api 封装层 |
| 模块间直接函数调用 | 走 Event Bus |
| Python 和 Rust 同时写同一张表 | 单一写入者（core） |

### 数据红线
| ❌ 禁止 | ✅ 应该 |
|---------|---------|
| 存文件本体、聊天全文 | 只存索引与配置 |
| 明文存 API Key | 系统凭据库 + 引用名 |
| 把用户数据发给未授权 Provider | 权限校验 + 显式授权 |
| 直接删表改字段 | 只增不改的 migration |

### 体验红线
| ❌ 禁止 | ✅ 应该 |
|---------|---------|
| 固定 sleep 等窗口就绪 | 轮询检测就绪状态 |
| 串行启动软件 | 并发启动 |
| 单个失败中断全流程 | 记录 + 继续 + 汇总 |
| 报错给用户看堆栈 | 给可读提示 + 解决建议 |
| 无流式的 AI 输出 | 逐字流式 + 可中断 |

### 扩展性红线
| ❌ 禁止 | ✅ 应该 |
|---------|---------|
| 硬编码模型名/路径 | 配置化 |
| 业务代码直接发模型 HTTP 请求 | 走 Provider 抽象 |
| 为了让某插件跑起来在核心加特判 | 回头改架构 |
| 插件默认有权限 | 默认零权限 |

### 自主性红线（AI 相关）
| ❌ 禁止 | ✅ 应该 |
|---------|---------|
| AI 自动改学习进度 | AI 建议，用户确认 |
| AI 自动写入个人档案 | 待确认队列 |
| AI 生成内容当事实展示 | 标记"AI 建议" |
| 无确认执行破坏性动作 | 逐次确认 |

## 四、优先级决策规则

当资源冲突、时间不够、需要砍功能时，按此顺序保：

```
1. 工作模式引擎（核心创新，最高）
2. 窗口自动布局
3. 软件管理
4. Dashboard
5. AI 侧栏
─────────── 以上是 MVP，不可砍 ───────────
6. 学习系统
7. 个人档案
8. 项目管理
9. 插件系统（架构必须预留，实现可延后）
10. 生活中心
11. 设备中心
12. 桌面小组件
13. 娱乐模式 / 社交
```

**砍功能时的铁律**：宁可少一个功能，不可破坏架构。插件接口、Provider 抽象、Event Bus、单一写入者——这四样即使功能不做，架子也必须先立起来。
