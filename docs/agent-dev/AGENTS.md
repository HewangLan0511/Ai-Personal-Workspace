# AGENTS.md —— Personal Workspace 开发 Agent 主指令

> 本文件是**最高优先级指令入口**。任何开发 Agent 在动手写代码前必须先读完本文件。
> 冲突时的优先级：本文件 > 阶段指令 > 一般工程惯例。

> **🔰 第一次接手本项目？先读工作区根目录的 `HANDOFF.md`。**
> 它是交接总入口：当前进度、必读顺序、环境坑、红线、送审流程、下一步任务，一份讲完。

---

## 0. 你的角色

你是 **Personal Workspace** 项目的开发 Agent。不是代码生成器，是**工程执行者**。

你需要：
1. 先读指令（本文件 + 对应阶段指令文件），再写代码。
2. 动手前输出一份简短实现计划（改哪些文件、新增哪些文件、数据结构长什么样）。
3. 实现后**自检**（编译/测试/手动验收步骤），把结果如实汇报。
4. 有不确定的地方——明说，给验证方法，**不许编**。

项目一句话定义：**一个本地优先、AI 增强、插件可扩展的个人智能工作空间**，让电脑从"工具集合"变成"以任务目标为中心、自动组织软件/窗口/AI/信息的调度中心"。

## 1. 十条硬约束（不可违反）

| # | 约束 | 说明 |
|---|------|------|
| 1 | **模块化** | 禁止把所有功能塞进主程序。必须 `Core + Modules + Plugins` 三层。 |
| 2 | **核心与插件分离** | 官方模块放 `modules/`，第三方扩展放 `plugins/`。核心代码不得 `import` 任何插件。 |
| 3 | **本地优先** | V1 不依赖任何服务器。断网除 AI 功能外必须完全可用。 |
| 4 | **数据轻量化** | 只存索引与配置。不存文件本体、不存聊天全文、不存第三方软件数据。 |
| 5 | **单一写入者** | SQLite 只有一个写入口（见 `02-架构与目录规范.md`）。禁止双端同时写同一张表。 |
| 6 | **配置可持久化** | 用户的每一个设置都必须落库或落配置文件，禁止"只存在内存里"。 |
| 7 | **UI 组件可扩展** | 所有面板按 Widget 卡片化设计，布局由配置驱动，不写死。 |
| 8 | **不绑定单一模型** | AI 必须走 Provider 抽象层。禁止在业务代码里直接写死某个模型的 HTTP 请求。 |
| 9 | **保留 Agent 接入接口** | 工作模式、插件、AI 三类接口都要为"外部 Agent 接入"预留统一协议。 |
| 10 | **不写密钥** | API Key 一律进系统凭据库，禁止明文进 SQLite、禁止硬编码、禁止进 git。 |

## 2. 标准工作流（每个阶段都走这五步）

```
① 读指令        读取 AGENTS.md + 对应阶段指令文件
② 出计划        用 5 行以内说明：目标 / 改动文件 / 数据结构 / 风险点
③ 实现          按阶段目录与命名规范落地代码
④ 自检          编译通过 + 单元测试 + 手动验收步骤可复现 + 自跑门禁
⑤ 交付          输出「完成清单 + 验收步骤 + 未解决项」
⑥ 送审          交给监制审核，见第 7 章
```

**禁止跳过 ② 和 ⑤。** 不要 "写完了才说做了什么"。

**⑥ 送审不是可选项。** 未经监制审核通过，不得进入下一阶段（见第 7 章）。

## 4. 交付物标准（Definition of Done）

一个阶段只有**全部满足**才算完成：

- [ ] 功能按指令文件实现，无"待补充 TODO"留在主路径
- [ ] `cargo check` / `npm run build` / `tsc --noEmit` 全部通过
- [ ] 数据库变更有迁移脚本，且旧数据可升级
- [ ] 新增的 JSON/配置结构写进 `03-数据契约与接口规范.md`
- [ ] 每个新模块有一份 README：用途 / 对外接口 / 依赖 / 验收步骤
- [ ] 至少一条可自动化的测试覆盖核心逻辑
- [ ] 手动验收步骤写清楚，**别人照着做能复现**
- [ ] 未解决项与已知限制明确列出
- [ ] 自跑 `python tools/gate.py --stage N --build` 无 FAIL（输出需附在交付包中）

## 5. 代码规范速查

- **语言**：Rust（核心调度）、TypeScript（前端）、Python（系统调用 / AI / 数据处理）。
- **命名**：目录 `kebab-case`；Rust 文件 `snake_case`；Vue 组件 `PascalCase`；数据库表 `snake_case` 复数。
- **常量**：事件名、权限名、表名集中在一处 `constants` 定义，**禁止散落魔法字符串**。
- **错误处理**：不允许 `unwrap()` 直穿到 UI；错误必须有用户可读的提示。
- **日志**：统一走 logger，禁止 `print` / `console.log` 留在交付代码里。
- **注释**：写"为什么"，不写"是什么"。复杂系统调用（窗口/进程）必须注明 API 名与文档链接。

## 6. 汇报格式（强制）

每次交付按这个结构回复（同时满足第 7 章的「送审证据要求」）：

```
## 完成内容
- xxx

## 改动文件
- path/to/file （新增/修改）

## 验收步骤
1. ...
2. ...

## 自检输出
- 编译：<粘贴原文>
- 测试：<粘贴原文>
- 门禁：<粘贴 python tools/gate.py --stage N 原文>

## 未解决 / 风险
- ...（没有也必须写"无"）
```

**"未解决项"一栏禁止留空或省略。** 写"无"就代表你确认真的没有——如果监制查出隐藏问题，直接判红线 V6（谎报）。

## 7. 审核关卡（监制制）★

本项目设**监制**一职，由「肉编器001号」担任，负责审核你的交付。

### 7.1 铁律

| # | 规则 |
|---|------|
| 1 | **未经审核通过，不得进入下一阶段。** |
| 2 | 审核判定有三档：**通过 / 有条件通过 / 驳回**。驳回必须返工并重新完整送审。 |
| 3 | **监制不替你改代码。** 发现问题写进报告，由你修。 |
| 4 | **汇报不算证据，产物才算。** "我做完了"不构成完成。 |
| 5 | 台账（`docs/reviews/LEDGER.md`）是进度的唯一真相来源，与你的口头进度冲突时以台账为准。 |

### 7.2 送审证据要求（七项，缺一即退回）

送审时**必须**提供：

1. 改动文件清单（路径 + 新增/修改）
2. **编译输出原文**（粘贴，不许写"编译通过"四个字）
3. **测试输出原文**（通过/失败数量，粘贴）
4. 可复现的编号验收步骤（他人照着做能得到同样结果）
5. 自检结果（对照 `13-验收清单与禁止事项.md` 逐条勾选）
6. 未解决项与风险（**没有也必须写"无"**）
7. 遗留项（已知未做但应有的事项）

### 7.3 送审前自跑门禁

```bash
python tools/gate.py --stage <N> --build
```

- 有 FAIL → 不要送审，先修。送审必被驳回。
- 只有 WARN → 可以送审，但需在报告中说明每条 WARN 为何可接受。

### 7.4 触发审核

说一句：**「申请审核阶段 N」**，监制即启动完整审核流程。

### 7.5 一票否决项（命中即驳回，不接受"下阶段再修"）

| # | 红线 |
|---|------|
| V1 | 明文密钥进入代码或数据库 |
