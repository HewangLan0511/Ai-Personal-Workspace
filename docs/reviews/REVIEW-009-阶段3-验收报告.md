## 一、目标达成（07 的「验收一句话」）

> **验收一句话**：点一个模式，多个软件窗口在 3s 内自动排列成四宫格。

`tools/verify_stage3.py` 端到端核验（**9/9 通过**，第 10 项由单测覆盖）：

```
PASS  1  查找窗口（含无窗口返回 null）
      找到 4/4 个主窗口；空 pid 返回 null=True；标题=['DirectX 诊断工具','系统信息','关于"Windows"','颜色管理']
PASS  2  定位窗口（GetWindowRect 复核 ±2px）
      目标={'x':120,'y':90,'w':700,'h':480} 实测={'x':120,'y':90,'w':700,'h':480} 偏差=[0,0,0,0]   ← 零误差
PASS  3  四宫格（4 窗口无重叠）
      placed=4 skipped=0 failed=0；实测=[(0,0,1280×720),(1280,0,…),(0,720,…),(1280,720,…)]；重叠=False
PASS  4  最大化恢复（取消最大化后能正确定位）
      最大化后={'x':-9,'y':-9,'w':2578,'h':1458} → 复位后精确回到目标
PASS  5  激活（成为前台窗口）        foreground=True
PASS  6  AI 侧栏留位                 工作区=2560×1440；侧栏起点≈1920；窗口右边界=1920（恰好不侵入）
PASS  7  多显示器                    显示器=[(0,0,2560),(1,-1600,1600)]；窗口x=-1600（第二屏起点）
PASS  8  高分屏（物理像素 + 比例）    工作区=2560×1440（物理像素）；每格宽实测 1280 = 应得值
PASS  9  容错                        未注册软件 → skipped_not_running，其余 placed=1
合计 9/9 通过
```

**方法论**：不采信接口自述 —— 每次定位后都用 `GetWindowRect` **读回实际矩形**比对。
"接口说移动了"不算，窗口真的在那个位置才算。

**关于验收项 8（DPI）的推理**：本机 DPI = 120（**125% 缩放**，非 07 举例的 150%）。
判据不是"缩放到 150%"，而是**工作区读数是否为物理像素**：
`/api/v1/monitors` 返回 work area = **2560×1440**，等于显示器物理分辨率 ——
说明 `PER_MONITOR_AWARE_V2` 已生效（若漏声明，读数会是 2048×1152 的虚拟化值）。
四宫格每格 1280 也正好是 2560 的一半，比例未被缩放影响。

## 二、无致命漏洞

| 项 | 结论 |
|----|------|
| 红线 V1~V8 | 未命中（本阶段不碰密钥 / AI / 插件；窗口移动可逆，非破坏性操作） |
| **ADR-001** | 遵守：窗口控制全在 Rust（`windows` crate）。`system/` 无同类实现，门禁 A031 通过 |
| 单一写入者 | 未触碰数据库写入路径；布局只读 `config/layouts/*.json` |

| 前台锁定 | `activate()` 走 `AttachThreadInput` → `BringWindowToTop` → `SetForegroundWindow`，实测 `foreground=True` |
| 单窗口失败不阻塞 | `apply.rs` 对每槽独立处理，失败仅发 `WINDOW_LAYOUT_FAILED` 后继续（07 §工程要求） |
| 等窗口就绪 | 验收脚本给 12s（dxdiag/msinfo32 启动慢），07 §禁止事项「不要在窗口还没创建完成时立刻定位」 |
