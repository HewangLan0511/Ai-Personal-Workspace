## 4. ⚠️ 三个需要你拍板的点（未确认前不动）

### A. `core/target/release/bundle/` 里有 **V0.1 唯一的两份安装包**

```
core/target/release/bundle/msi/Personal Workspace_0.1.0_x64_en-US.msi   18.0 MB
core/target/release/bundle/nsis/Personal Workspace_0.1.0_x64-setup.exe  15.1 MB
```

全仓扫描（`find` 排除 `core/target` 后的 `*.msi` / `*.exe` / `*nsis*`）**没有找到任何副本**。
也就是说：直接删 `core/target/` 会把 V0.1 的正式安装包一起删掉。

| 选项 | 后果 |
|---|---|
| **A1（建议）** 先复制到 `release/V0.1/` 再删 `target/` | 安装包留档（+33.1 MB），清理后总量 ≈ 58 MB |
| A2 直接删 `target/`（含安装包） | 清理后 ≈ 25 MB；安装包需日后 `tauri build` 重打 |
| A3 保留 `core/target/release/bundle/` 不删 | 清理后 ≈ 58 MB，但 `target/` 残留，不算"干净归档" |

### B. `core/binaries/service-x86_64-pc-windows-msvc.exe`（9.0 MB）

未被 git 跟踪，是 Python sidecar 经 PyInstaller 打出来的运行时二进制（源码在 `system/`，保留）。
按"可重新生成的构建产物"口径可删；但它**不在 `target/` 下**，删了以后归档仓若直接 `tauri build`
会缺 sidecar。建议：**保留**（9 MB，占比极小，换"归档仓可直接构建"）。

### C. `.workbuddy/tmp/`（0.1 MB / 24 文件）

内容是 `cargo-check.log` / `npm-install.log` / `cwd-probe.log` 等临时日志。
它在特殊保护名单 `.workbuddy/` **之内**。默认**不动**；若要连它一起清，请明确指示。

### 清理后的一处连带影响（提前告知）

`tools/verify_*.py` 的 D 段（真实环境验收）要求 `ui/dist` 存在且不早于 `ui/src`。
删除 `ui/dist` 后，归档仓里**直接跑这些脚本会因"dist 不存在"而 NOT RUN** ——
恢复开发时需先 `python tools/_fusion_build.py`（同源构建，约 10 秒）再跑验收。
这符合"构建产物可重新生成"的归档口径，仅作提醒。
