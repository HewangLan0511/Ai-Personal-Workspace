## 4. 执行过程中修正的两处问题

### 4.1 日志去留名单曾被"自引用"污染（已修正，结论未变）

删除前按审计文档§6 复算名单时，第一次用宽口径（把 `.py/.ts/.vue/.json` 也算作引用来源，
且用子串匹配）得到 **60 保留 / 9 删除**，与审计的 27/42 严重不符。

排查后确认是两处误判叠加：

1. `tools` 下的日志名大量命中源码里的变量名子串（假引用）；
2. **审计文档自身就列举了这几十个日志名**，把它算进语料后形成自引用，
   使 `_v01_reg_c6.log` / `_v01_solo_c5.log` 等被误判成"被引用"。

收紧为「只在 `*.md` 中精确匹配完整文件名，且排除归档清理文档自身」后，
得到 **27 保留 / 42 删除，与审计文档逐条一致**。审计结论正确，第一版复算方法有误。

保留的 27 个日志均有明确出处（例：`_v01_reg_c1~c5.log` ← `V0.1-FINAL-report.md`；
`_c7_run1/run2.log` ← `TECH-07-C7-implementation-report.md`；`_c4_rerun.log` ← `V0.1-FINAL-audit.md`）。

### 4.2 `tools/` 清理后仍有 8 MB，检查后判定保留

`tools/` 的 8 MB 几乎全是验收截图（`_force_shots/` 3.4 MB、`_fusion_shots/` 2.0 MB、
`_full_shots/` 0.6 MB 等 PNG），属验收证据而非构建产物，且不在审计 DELETE 清单内 → 保留。

## 6. 一处连带影响（提前告知）

`tools/verify_*.py` 的 D 段（真实环境验收）要求 `ui/dist` 存在且不早于 `ui/src`。
删除 `ui/dist` 后，归档仓里直接跑这些脚本会因「dist 不存在」而 **NOT RUN**。
恢复开发时先跑一次同源构建即可（约 10 秒）：

```bash
python tools/_fusion_build.py   # typecheck + VITE_CORE_BASE='' 同源 vite build
```

再补 `npm install` 与 `cargo build` 即可恢复完整开发/验收能力。
