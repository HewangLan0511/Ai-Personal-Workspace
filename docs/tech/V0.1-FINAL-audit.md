## 三、重点问题与处置方案（均待拍板）

### 1. `ui/dist` 历史 chunk 累积（P2）

- 实测 778 个 assets，其中同名前缀多份（index ×42、SoftwareView ×39…）= 历次构建残留。
- 根因：`vite.config.ts` **`emptyOutDir: false`**，附书面理由（2026-09-14，规避沙箱批量删除保护对构建的误伤）。
- 方案 A（推荐）：Phase 2 先手动清空 `ui/dist` 一次 → 保持 `emptyOutDir: false` + 构建后由 verify 前置动作或文档化命令清理。理由：**不改构建行为**（注释理由仍有效），满足"不持续累积"靠一次性清理+口径。
- 方案 B：改回 `emptyOutDir: true`（Vite 默认），构建时自清；若沙箱问题复现则回退方案 A。
- 两案都不触碰运行逻辑；Phase 2 构建完成后 dist 体积应回到 ~4MB 量级。

### 2. `personal-workspace-ui/` 定性（结论：视觉参考，保留）

- 全仓引用检索：仅 3 处且**全部是注释**（primitives.css / router / RunView 的"原型对照"），不参与构建、无运行时依赖。
- 定性：**必须保留的视觉参考/设计资产**（UI-FUSION-STANDARD 的对照物）。不删除、不归档移动（移动会破坏注释里的路径语义）。

### 3. `core/target` 9GB（P3，登记不处理）

- release 2.7GB 是验收脚本的被测产物（红线教训："改了源码≠改了被测物"），**必须保留**。
- debug 6.3GB 仅开发态使用，可清理后按需重建，但重建耗时且本阶段收益仅磁盘 → **登记 backlog，不在 V0.1 处理**。

### 4. git 基线未提交（P1，建议本阶段收口动作）

- 仓库仅 2 个历史 commit；TECH-07 C1~C7 全部工作、V0.1 清理均处于未提交状态（git status 大面积 M/??）。
- `ui/dist`、`core/target` 已被 .gitignore 覆盖（check-ignore 实测通过，红线 V8 无风险）。
- **建议**：Phase 2 清理+回归全绿后，做一次正式 commit（V0.1 baseline）+ 打 tag。是否执行由白宇拍板（提交策略属你的决定域）。
