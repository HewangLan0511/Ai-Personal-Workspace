# Default UI 产品体验校准（default-ui-review.md v1.0）

> 校准对象：`index.html` 全部页面 · Default Skin（零覆盖）+ Motion Token 基线
> 本轮只做**判断与建议**，不改代码。所有建议不新增功能、不修改架构、不设计新 Skin、不引入复杂动画。
> 优先级：**P0 影响产品定位 / P1 影响体验 / P2 视觉优化**

---

## 一、总评（结论先行）

**骨架已经是"桌面工作台"，不是管理后台。** 三侧栏结构（导航 236 · 主视窗 · 组件区 224 · AI 侧栏 360）、
全局常驻 AI、IDE 式工作模式（appbar + 窗口舞台）、设置沉底且开发者模式默认收起——这四件事撑住了定位。

剩余问题集中在三件事：
1. **高频页塞了低频内容**（首页右栏是 CPU/内存监控，"今日任务"反而只是组件区小卡）；
2. **个别页有"官网/商店感"**（项目页装饰横幅、插件页商店式 CTA）——工作台应该用真实内容占位，不放插画位；
3. **动效数量已经够、克制是对的**，唯一缺口是工作模式窗口拖动落位没有空间感反馈（token 已有，没接上）。

模块权重现状：工作软件 ✓（hero + 最近使用）、AI 助手 ✓（全局侧栏，任何页都在）、
**今日任务 ✗**（三件套里唯一缺位的高频项）。设置/插件/设备已正确弱化 ✓。

## 三、问题列表（按优先级）

### P0 —— 影响产品定位

**P0-1 首页右栏「今天」装的是系统监控，不是今日任务。**
- 现状：右栏 = 使用时长 + spark 图 + **CPU 32% / 内存 12.4GB** + 「我的设备」入口卡。
  CPU/内存是管理后台的指标语言，出现在全产品最高频的页面上，直接违反"工作台不是管理系统"。
- 同时"今日任务"作为定义的高频三件套，只存在于组件区的小 wcard 里，首页主体没有位置。
- **建议（不改功能，只动既有内容的权重与位置）**：
  1. 右栏「今天」卡主体换成**待办清单**（组件区 todo widget 的三条真实任务原样上移，勾选交互已有）；
  2. 使用时长压缩为卡头一行小字（保留 tabular-nums 的 t-num）；
  3. **删掉 CPU/内存两行**（device 页已有完整版，重复展示没有增量信息）；
  4. 「我的设备」入口卡保留但降为 ghost 样式——设备管理在首页的正确形态是入口，不是仪表盘。

**P0-2 首页第一视觉焦点分裂。**
- 现状：`t-display` 级问候语（"晚上好，白宇"）与 Hero 卡的 `btn--primary btn--lg`「继续工作」争夺焦点。
  问候语占的是页面最大的字号，但信息量最低（日期+使用时长一行可带完）。桌面工作台的参照物
  （macOS 桌面 / Notion / IDE）都没有把"打招呼"做成视觉主角。
- **建议**：问候语降一级（t-page），把让出的空间还给 Hero——Hero 的「继续工作」应是唯一主动作。
  「准备开始什么？」这行 section 标题可并入问候副行，减少一层排版。

### P1 —— 影响体验

**P1-3 项目页的 120px 渐变横幅 + SVG 插画是"官网感"来源。**
- 工作台不放装饰位。项目卡的信息（阶段/最近活动/进入按钮）本身撑得起这张卡。
- **建议**：横幅替换为**真实内容的迷你窗口缩略**（首页 wsCard 已有 `minimap(w.layout)` 组件，直接复用）
  ——既消掉插画感，又和首页工作空间卡形成同一套视觉语言。

**P1-4 AI 双入口概念重叠。**
- 现状：导航有独立 AI 页（聊天/工作空间助手 tab），全局又有 AI dock，两处是几乎相同的消息 mock + 输入框。
  产品主张"AI 是常驻工作台的一部分"（dock 已实现），独立页的存在让概念回摆。
- **建议**：不删功能、不动架构。① 导航里的 AI 项保留（divider 区已经矮化了它）；
  ② 页面版定位语改成"聚焦会话"语义（文案层面与 dock 的"随手问"区分）；
  ③ 权限卡/气泡/建议 chip 两处已共用样式，保持，不另起炉灶。

**P1-5 生活区 4 列等权网格，没有焦点也没有工作台语言。**
- 天气/音乐/消息/今日使用四张卡权重相同，读起来像"信息面板"。生活区是低频页，但既然存在，应该一眼有主体。
- **建议**：把「今日使用」（已有 spark，是全页唯一与"工作"有关的数据）升级为 span2 主体位置，
  音乐（有播放控件，交互最重）保持 span2，天气/消息降为 1 列小卡。只调 grid span，零新组件。

**P1-6 插件页的商店感。**
- 「获取更多插件」是全页唯一的 `btn--primary`，"可发现"区做成三张推荐 tile——低频页配了商店级 CTA。
- **建议**：主按钮降为 `btn--secondary`；「可发现」标题改「更多组件」并压缩 tile 高度。
  低频页的视觉音量应该整体小半档。

**P1-7 工作模式窗口拖动没有"落位"反馈。**
- 手动调整模式下窗口 move/size 是纯几何跟随，松手无任何确认。拖动换位的空间感
  （motion-system 里 reorder/drop 场景、`--mt-dur-highlight` token）在首页网格已接上，舞台窗口没接。
- **建议**：松手时对被拖窗口复用**已有的** drop 高亮（`just-swap` / `--mt-dur-highlight`），
  零新动画、零新 token。对齐线之类的增强明确**不做**（违反"不引入复杂动画"）。

### P2 —— 视觉优化

**P2-8 学习页/项目页单内容撑满全宽，偏空。**
- 单条主线/单个项目是真实数据状态，不是布局错误。建议：内容区限宽（复用 `--content-max` 思路），
  卡片不无限拉伸；不加"空状态插画"。

**P2-9 档案页 AI 建议卡权重偏高。**
- 通知性质的内容占了页面第二位（brand-50 底 + dashed 边，视觉音量接近主卡）。
  建议：改普通 card + 左侧 2px brand 描边，字号不变，音量降半档。

**P2-10 首页纵向密度。**
- greet + hero + 最近使用 + 工作空间网格四段都在首屏附近，section 间距（--gap-section 32px）下
  网格大概率出首屏。可接受（工作台允许滚动），仅建议最近使用的 `sort-hint`（"可拖动排序 · 右键更多"）
  改 hover 才显现——低频提示常驻会抬高扫描噪音。

**P2-11 Skin Lab 色板标签裸露 token 名。**
- `brand-500`/`surface-1` 等 token 名直接当标签，对设计师是验证场、对产品是开发态残留。
  保持现状可接受（该页定位就是验证场），若收紧：token 名降为小号 mono 副行。

## 四、动效存在感核查（结论：数量克制是对的，别加）

| 检查点 | 结论 | 依据 |
|---|---|---|
| hover 有反馈 | ✓ | 卡片 shadow-sm+border、app-square 抬起、行内操作 hover 才显现（apps 页 hover-only） |
| press 自然 | ✓ | `--mt-press` scale .985 / 80ms，无回弹，全站统一 |
| 页面切换稳定 | ✓ | scene-in 只动内容区 160–220ms，快速连点只到最后一页 |
| 拖动换位空间感 | ⚠ 部分 | 首页网格 reorder 160ms 让位 ✓；**工作模式窗口落位无反馈**（见 P1-7，接已有 token 即可） |
| 三档降级 | ✓ | off 档 hover/状态仍可见（本轮已验证）；skin-sandbox 三档 computed 值 1/.55/1.35 有端到端证明 |

**明确不做**：入场 stagger 加深、滚动视差、窗口拖动对齐线、卡片入场逐个飞入。
现有 12 个场景 + 三档降级已经是"工具存在但不抢戏"的正确状态。

## 五、正向清单（这些是对的，后续不要"优化"掉）

1. 三侧栏 + 全局 AI dock + 插件组件区——工作台的空间骨架。
2. 设置沉底 + 开发者模式默认收起 + 插件/Skin Lab 不进主导航——低频弱化已到位。
3. 卡片靠描边不靠阴影、无毛玻璃、圆角 ≤20——Default Skin 的纸面模型。
4. 工作模式的 appbar + 窗口舞台 + 门限 240ms 即可交互——最核心的"工作台瞬间"。
5. 折叠⇄展开的连续跟手 + 120ms 文字渐显——上一轮刚校准过的手感，别动。

## 六、建议执行顺序

1. **P0-1 / P0-2**（首页右栏换血 + 焦点唯一）——收益最大，只动首页模板与右栏内容来源；
2. **P1-3 / P1-6 / P1-7**（消官网感/商店感 + 接 drop 高亮）——都是小改动；
3. **P1-4 / P1-5**（AI 双入口文案定位 + 生活区 span 调整）；
4. **P2 批量**（限宽、音量降档、hover 化提示）。

每批做完跑一轮既有验收（`verify_s2_local_diff.py` 6 条 + `verify_collapse_expand.py` 4 条 + 语法门禁），
首页动了模板后按 MEMORY 铁律必须重跑两组端到端。
