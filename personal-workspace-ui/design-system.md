## 1. 设计立场（一句话）

**这不是一个"功能列表"，是一台电脑的工作台。**

用户来这里不是为了配置系统，是为了回答一个问题：**我现在要做什么？**
所以每个页面的第一屏都必须回答它，其余内容按"需要时才出现"排布。

判断一个设计对不对，只用一条标准：

> 这个界面是在向用户**索取信息**（填路径、选协议、开关权限），还是在**交付结果**（环境已就绪、这是你常用的、下一步是这个）？
> 索取 → 降级到高级设置；交付 → 放在主界面。

---

## 2. 四条设计原则

| 原则 | 含义 | 落地规则 |
|---|---|---|
| **意图优先** | 用户表达"我要做什么"，系统负责准备环境 | 任何需要用户先理解系统概念才能操作的流程，都必须重做 |
| **默认简单，复杂度渐进** | 三级：普通 → 高级 → 开发者 | 路径/参数/Provider/Endpoint/Protocol/Capability/插件开发信息，默认全部不可见 |
| **结果是主角** | 展示"正在播放什么歌"，不展示"IMAP 已连接" | 技术配置只在设置页，且带明确的"高级"标记 |
| **克制** | 少描边、少阴影、少强调色、少动效 | 一屏最多一个主按钮；状态色只在 badge / dot / 错误态出现 |

## 3. 视觉方向：结构语言「窗口即纸面」

这是整个产品**不像后台管理系统**的根，也是本次设计最核心的一个决定。

后台管理系统的结构是：`白底 + 一堆带边框的卡片`。
本产品用三层嵌套，做出"桌面上放着一块工作台"的空间感：

```
┌──────────────────────────────────────────────┐
│ ① 窗口层  #EBEDF1                            │  ← 桌面感的底，绝不用纯白
│  ┌────────────────────────────────────────┐  │
│  │ ② 工作台面板  #F4F5F8  圆角 20  内缩 10 │  │  ← 像桌上的一块面板
│  │  ┌──────────┬───────────────────────┐  │  │
│  │  │ ③a 侧边栏 │ ③b 内容区              │  │  │
│  │  │  #F8F9FB │  白色卡片浮在面板上     │  │  │
│  │  └──────────┴───────────────────────┘  │  │
│  └────────────────────────────────────────┘  │
└──────────────────────────────────────────────┘
```

规则：
- **卡片不靠描边分组，靠"白卡片浮在浅灰面板上"的色差分组。** 描边只用 `#EDEFF3`（几乎看不见）作为边界保险。
- 只有**浮层**（Modal / Drawer / Popover / Toast）允许用大阴影。静态卡片最多 `shadow-sm`，hover 才 `shadow-md`。
- 工作空间进入运行态时，这层结构**收得更紧**：侧边栏图标化、顶栏换成工作空间名 + 状态、主区变成一块"窗口编排画布"。

#### B. 拖拽规范

| 场景 | 语义 | 视觉反馈 |
|---|---|---|
| 工作空间卡片 | **交换位置 + 继承被交换对象的视觉占比** | 拖起项 opacity .35；目标项 2px 主色 outline |
| 最近使用的软件 | 插入排序（尺寸相同） | 同上 |
| 组件区卡片 | 插入排序 | 同上 |
| 自定义抽屉里的编排行 | 插入排序 | 同上 |

- 拖拽态统一：`.dragging{opacity:.35}` + `.drop-target{outline:2px brand-400}`。**禁止**位移动画、占位幽灵块以外的复杂效果。
- **工作空间交换尺寸**是关键：网格的槽位尺寸固定，卡片换位置后呈现新槽位的大小。
  即 `swap(index)` 之后再 `swap(size)`，净效果是"我把常用的拖到大位置，它就变大"。
- **任何手动拖拽都会把布局模式自动切成「固定布局」** —— 用户手动调过就必须尊重，不能被自动排序覆盖（任务书 §11）。
  切换时**只改那两个按钮的 class**，不重渲染整页。

#### B+1. 反"刷新感"硬约束（v1.3.1）

> 主人原话：「工作空间里的对象拖动换位后主页整体位置保持不变，不能产生类似刷新的效果。」

拖拽落点**只允许在 DOM 上局部换位**，全流程禁止调用整页 `render()`：

| 禁止 | 原因 |
|---|---|
| 拖拽回调里 `render()` | 整页重绘 + 入场动画重播 + `scrollTop` 归零 → 观感就是"刷新了一下" |
| 落点后 `view.scrollTop = 0` | 主页位置必须保持原样 |
| 交换后重放入场动画 | 同上，且会让其他模块跟着抖 |

实现约定（可直接照抄）：

1. `swapNodes(A,B)` —— 兄弟节点互换位置，不重建、不重绘（`insertBefore` 三分支写法）。
2. `swapSize(A,B)` —— **只**交换尺寸（`size-*` class token + 白名单里的尺寸型 inline style：
   `grid-column/grid-row/width/height/flex/aspect-ratio` …），让**槽位尺寸留在原处**，
   卡片内容换到新槽位 → 呈现"继承被交换对象的视觉占比大小"。
3. `flash(el)` —— 移除/重加 `.just-swap`，播放 460ms 的**纯 box-shadow** 高亮
   （`swapFlash` 关键帧不改任何会触发重排的属性），作为"我换了"的唯一提示。
4. 回调 `onReorder(from,to)` **只更新数据模型 + 静默播报 + 同步局部按钮 class**，不碰页面骨架。
5. 插入排序（最近使用 / 组件区 / 抽屉编排行）走 `insertBefore` 局部搬移，同样不重渲染。

判定标准：拖完一张卡片后，**页面滚动位置、其他模块的位置、入场动画状态三者都不变**，
只有两张卡片的内容与大小互换 + 一次 460ms 描边高亮。

#### B+2. 拖拽不给 Toast，改静默播报（v1.3.2）

> 主人原话：「对象交换位置不出现播报交换位置的信息。」

**凡是"结果肉眼可见"的操作，都不弹 Toast。** 拖拽换位、排序就属于这一类——卡片自己已经
换了位置、还闪了描边，底部再弹一条居中提示条纯属噪音，而且连续拖几下会糊成一叠。

| 操作类型 | 可见反馈 | 播报方式 |
|---|---|---|
| 拖拽换位 / 排序 / 缩放 | 元素本身动了 + 460ms 描边高亮 | **静默播报**：写进 `aria-live="polite"` 的 `.sr-only` 区，读屏念、屏幕不显示 |
| 删除 / 卸载 / 保存布局 / 恢复默认 | 元素消失或内容变化 | **Toast**：底部居中，2.2s 自动消失 |
| 破坏性操作 | 二次确认弹窗 | Toast 兜底（可撤销文案） |

实现要点：

```html
<div class="sr-only" id="liveRegion" role="status" aria-live="polite" aria-atomic="true"></div>
```
```js
function announce(msg){                 // 静默播报：不弹任何可见提示
  const r = document.getElementById('liveRegion');
  if(!r) return;
  r.textContent = '';                   // 先清空，保证同一句话能重复触发
  setTimeout(()=>{ r.textContent = msg; }, 30);
}
```

- 播报文案要说**人话的结果**，不是操作名：`「AI 项目开发」与「写作」已交换位置，AI 项目开发 现在是大卡片`。
- 尺寸用 `sizeName()` 转成"大/中/小卡片"，不要把 `size: 'l'` 这种字段值念出来。
- **组件区在抽屉里改顺序要当场生效**（`refreshWidgetCol()` 只重画那一列，同样不整页重绘），
  不要写"关闭后生效"——能立刻看到就别让用户猜。

#### B+3. 只换尺寸，其余参数跟着对象走（v1.3.3）

> 主人原话：「拖动换位后保持除大小之外的所有参数不变，例如明暗度和不透明度。」

**尺寸是槽位的属性，其余一切是对象自己的属性。** 交换时只允许尺寸发生转移。

| 参数 | 归属 | 换位后 |
|---|---|---|
| `size-l/m/s`、`grid-column`、`width/height`、`flex` | **槽位** | 留在原位置，谁进来谁继承 |
| 明暗度（`filter: brightness()`、暗态 class） | **对象** | 跟着卡片走 |
| 不透明度（`opacity`） | **对象** | 跟着卡片走 |
| 色调 / 强调色 / 边框 / 角标 / 动效状态 | **对象** | 跟着卡片走 |

反面教材（第一版就是这么写的，已废）：

```js
a.className = b.className; b.className = a.className;   // ❌ 连人带衣服一起换
a.setAttribute('style', b.getAttribute('style'));       // ❌ 对方的暗态、半透明会被换过来
```

正解是**白名单制**：只有下面这些算尺寸，其余一律不碰。

```js
const SIZE_CLASS_RE = /\bsize-[a-z]+\b/;
const SIZE_STYLE_PROPS = ['grid-column','grid-row','grid-area','width','height',
  'min-width','min-height','max-width','max-height','flex','flex-grow','flex-basis','aspect-ratio'];
```

判定标准：拖完换位后，**两张卡片除了占的格数变了，明暗、透明度、色调、角标、
动效状态与换位前一模一样**。给其中一张挂个半透明/暗态再拖，它换过去还是半透明/暗态。

#### C. 右键菜单（Context Menu）

新组件。跟随鼠标定位，自动避开视口右下边界。

```
┌────────────────────┐
│ VS Code            │ ← 头部（说明对谁操作）
├────────────────────┤
│ ▶ 启动              │
│ ＋ 添加到工作空间…    │
│ ▦ 在软件页中显示     │
├────────────────────┤
│ ✕ 从最近使用中移除   │
├────────────────────┤

```

| 规则 | 说明 |
|---|---|

| 高级项置底 | "高级设置…"这类入口放最后，与三级复杂度一致 |
| 关闭 | 点击别处 / 滚动 / Esc 都关闭 |
| 菜单项 | 高度 30，图标 15，圆角 6，hover `surface-3` |

#### D. 自定义工作台（统一入口）

首页问候语右上角一个 icon-button（tooltip「自定义工作台」），组件区底部"＋ 添加组件"，两个入口进同一个抽屉：

- **显示右侧组件区** 总开关
- **右侧组件**：拖拽排序 + 逐个显隐开关
- **首页模块**：当前工作 / 最近使用 / 我的工作空间 / 今天，逐个显隐
- **恢复默认**

> 这个入口刻意做得很小（一个 30px 图标按钮）。它是"调整完就走"的地方，不是日常入口。

> 守住的一条：组件区与首页模块必须**成对实现显示与隐藏**，且隐藏后首页不能出现塌陷的空白。关掉全部模块时首页退化为"问候 + 准备开始什么？"，仍然成立。

### 4.2 全局 AI 侧栏（v1.1：从"仅运行界面"提升为"任何页面都在"）

```

│        │                  │ 消息流        │
│        │                  │ [输入……]     │

┌────────┬──────────────────────────┬────┐

│ 侧边栏  │      当前页面内容          │ AI │
```

| 项 | 规格 |
|---|---|
| 展开宽度 | 360px（允许 320–380） |
| 收起宽度 | 48px 竖条：顶部主色图标按钮 + 竖排"AI 助手" + 底部模式小圆点 |
| 默认状态 | **展开**（宽窗口）；窗口 ≤1180px 时自动收成竖条，用户主动展开才覆盖（`.force-open`） |
| 两种模式 | **聊天**（默认）／**工作区**（= 工作空间助手），顶部 segmented 切换 |
| 模式视觉区分 | 聊天：灰色权限条「🔒 不访问你的工作空间」；工作区：绿色权限条「● {工作空间名} · 已允许访问」+ [管理] |
| 输入框占位 | 聊天 "随便聊点什么…"；工作区 "问关于这个工作空间的事…" |
| 建议 chips | 两种模式各给不同的建议，不要复用同一套 |
| 运行界面 | AI tab 点击 = 展开侧栏 + 自动切到「工作区」模式；侧栏收起时舞台右下角出现浮动胶囊 |
| 与 AI 页面的关系 | AI 页面 = 沉浸式长对话（保留）；侧栏 = 随手问一句。两者共用同一套模式与权限语义 |

> 守住的一条：AI 依然**不是主角**。全局化之后更要靠"默认可收起 + 360px 上限 + 竖条只占 48px"来约束，不能默认占掉主内容区。

### 5.3 间距 / 圆角 / 阴影

- **间距**：`4 8 12 16 20 24 32 40 48`，语义化封装为 `--gap-inline(8) / --gap-stack(12) / --gap-card(20) / --gap-section(32) / --pad-card(20) / --pad-card-lg(24)`。
- **圆角**：控件 `6–8`，卡片 `12–16`，大容器 `16–20`。**禁止超过 20（除 chip / badge 全圆）**。
- **阴影**：4 级。`xs/sm` 静态层级，`md` hover，`lg` 只给浮层。

### 5.4 动效

| 场景 | 时长 | 缓动 | 表现 |
|---|---|---|---|
| hover / 按下 | 120ms | `cubic-bezier(.22,.61,.36,1)` | 颜色、阴影、1–2px 位移 |
| 卡片 hover | 160ms | ease-out | 上移 1–2px |
| 页面切换 | 220ms | ease-out | 淡入 + 上移 6px |
| 抽屉 / AI 面板 | 220ms | ease-out | 横向位移 |
| 侧边栏折叠 | 300ms | `cubic-bezier(.4,0,.2,1)` | 宽度变化 |

**禁止**：回弹/弹性缓动、粒子、大幅飞入、缩放 > 1.02、渐变发光。

## 7. 状态规范

### 7.1 空状态（禁止出现"暂无数据 / 0"）

三段式：**图标 + 一句人话 + 一个主行动**。

```
        ┌──────────────────────────────────┐
        │            ▢ (56)                │
        │       还没有添加软件              │
        │  把常用的软件加入工作台，         │
        │  之后可以直接从工作空间启动。      │
        │        [  添加软件  ]             │
        └──────────────────────────────────┘
```

| 位置 | 文案 |
|---|---|
| 软件为空 | 还没有添加软件 / 把常用的软件加入工作台，之后可以直接从工作空间启动。/ [添加软件] |
| 工作空间为空 | 还没有工作空间 / 创建一个工作空间，让 Personal Workspace 帮你准备工作环境。/ [创建工作空间] |
| 首页无当前工作 | 还没有正在进行的工作 / 选择一个工作空间，或者从当前打开的窗口创建一个。/ [创建工作空间] |
| 插件为空 | 还没有更多插件 / 插件可以让工作台显示天气、音乐、消息等内容。/ [获取更多插件] |

### 7.2 加载状态

- **禁止** `Loading...` 文字块。
- 列表/卡片 → 骨架屏（与真实内容同尺寸，避免抖动）。
- 动作进行中 → 16px spinner + 一句说明（例："正在扫描电脑中的应用…"）。
- 首屏加载 → 骨架屏，不用全屏遮罩。

### 7.3 错误状态

```
┌─────────────────────────────────────────┐
│ ⚠  暂时无法启动 VS Code                  │
│    请检查软件是否仍然安装，或者重新选择一次。│
│    [重新尝试]  [查看详情]                 │
└─────────────────────────────────────────┘
```

- 主文案必须是**用户能理解的结果**，不是错误码。
- 技术信息（路径、错误栈、`failed to invoke command`）**只允许**出现在「查看详情」里。
- 可恢复的给主按钮（重新尝试），不可恢复的给引导（去设置里重新选择）。

### 7.4 权限状态（AI 访问工作空间）

必须让用户一眼看懂 AI 现在能做什么：

- 未授权：`AI 项目开发 · 未授权访问`（灰点）
- 已授权：`● 已允许访问当前工作空间`（绿点 + success-soft 底），旁边常驻 [管理权限]
- 普通聊天页：常驻一行 `🔒 当前对话不会读取你的工作空间、文件与应用状态。`

**普通聊天 与 工作空间助手 必须视觉可区分**：前者是普通聊天布局（顶部锁提示），后者顶部有绿色权限条 + 建议动作 chips + 输入框占位文案不同。

## 11. 图标体系

- 统一 **24 网格 · 线宽 1.6 · 圆头圆角**，单一来源（原型中是 SVG symbol 表）。

## 12. 无障碍与文案

- 正文对比度 ≥ 4.5:1，大字 ≥ 3:1；`--text-4` 只用于占位符与禁用态。

## 13. 开发落地备注

1. **Token 单一来源**：前端只消费 `tokens.css` 的变量，组件里禁止出现十六进制色值。暗色主题通过 `:root[data-theme="dark"]` 整体映射，组件零改动。
2. **Mini Map 数据**：工作空间实体新增 `layout: [{app, x, y, w, h}]`（百分比）。运行界面拖动/缩放后写回同一结构，"保存布局"就是持久化它。
3. **运行界面**：窗口 DOM 用百分比定位，不要 px——窗口 resize 时布局自动等比。
4. **侧边栏折叠**：只改 CSS 变量 `--sidebar-w` 的生效值（`.shell.mini`），300ms `ease-in-out`。
5. **三级复杂度**：不要把"高级字段"渲染后再用 CSS 隐藏，应该在渲染层就按用户模式决定是否生成。
6. **动效降级**：统一走 `[data-motion="reduced"]`，不要在每个组件里写 `prefers-reduced-motion`。
   完整动效规范见 **`motion-system.md`**（独立文档，v0.2）。
7. **空/加载/错误**三态必须成对实现，不允许任何列表只有一个 happy path。

## 12.5 动效（Motion）· 已锁定决策

> 完整规范（场景清单 / 逐场景参数 / Token 表 / Skin Engine 接管 / 实现顺序）见 **`motion-system.md`**。
> 本节只放**必须被 Design 与前端共同遵守的硬约束**，避免两份文档打架。

### 12.5.1 Duration 与 Intensity 是两个独立维度（D2）

| 维度 | Token | 管什么 |
|---|---|---|
| **Motion Duration（节奏）** | `--mt-dur-instant/quick/base/panel/scene/cinematic` | 动**多久** |
| **Motion Intensity（幅度）** | `--mt-intensity`（默认 1）+ `--mt-drift/--mt-scale-on/--mt-blur` | 动**多少**：translate 距离、scale 幅度、opacity 强度、blur / emphasis |

- **`--mt-intensity` 不是时长乘数。** 禁止 `calc(var(--mt-dur-*) * var(--mt-intensity))`。
- 所有幅度基元（`--mt-dist-*` / `--mt-scale-*` / `--mt-fade-*` / `--mt-shake-x`）由 intensity 派生；
  所有 duration 直接取 duration token。
- 后果：Skin 改一个 `--mt-intensity` 就能从"克制"切到"活泼"，**节奏保持不变**；
  要调节奏必须动 duration token。两个维度正交，可组合出"快而克制"或"慢而活泼"。
- 降级同理分两路：`reduced` 同时收窄 intensity **并**覆盖 duration（见 motion-system.md §E5）。

### 12.5.2 View Transitions 是增强项，不是依赖项（D1）

- Motion System **不依赖** View Transitions；支持才用，不支持自动走 CSS/JS 双段 fallback。
- 两条路径**共用同一批 `--mt-scene-*` token**，不允许两套参数。
- 提供 `?motion=novt` 强制走 fallback（保证 fallback 长期可测）。
- ⛩ **前置门限**：VT 之前必须先完成「局部更新不触发整页重绘与整页入场动画」改造并通过端到端验收。
  **VT 会掩盖而不是修复整页重绘**——它把重绘包装成一段合法过渡，问题从"看得见"变成"看不见"。
  门限不过，不允许进 VT 阶段。

### 12.5.3 工作模式进出：560ms / 240ms 门限（D3）

| 区间 | 内容 | 交互 |
|---|---|---|
| 0–240ms | 主体段：内容区退场、面板形态、stage 底纹、顶栏切换 | **阻塞，240ms 结束即恢复** |
| 240–560ms | 后台段：软件栏、AI 面板、Workspace UI、窗口落位、布局反馈 | **非阻塞，可被操作打断并跳终态** |
| 560ms | 稳定态 | — |

- 新增 `--mt-cinema-interactive-gate: 240ms`；**任何长时动效都必须声明自己的 gate**。
- 若实测证明 560ms 过长，**统一压缩到 ≈360ms**（按比例），不单独砍某一段——会破坏空间感。

### 12.5.4 与既有交互规范的关系

- §4.1 B+1「反刷新感」是动效的**前置条件**，不是并列项：任何场景级动画都不得由局部更新触发。
- §4.1 B+2「拖拽不给 Toast」继续有效：拖拽反馈 = 元素自身位移 + 描边脉冲，无浮层。
- §4.1 B+3「只换尺寸」继续有效：换位动画不得改写明暗度/不透明度。
- 新增微交互：`mt-press`（按下 `scale → --mt-scale-press`，80ms）——目前全项目缺按下态。
