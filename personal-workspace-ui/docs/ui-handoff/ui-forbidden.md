# 禁止事项清单 · Personal Workspace

> 交接文档 6/6。技术 Agent 接手后**改动前必读**。本清单是硬约束，不是建议；违反任何一条即视为破坏定稿。
> 例外流程：确需突破某条时，先出方案说明影响面，获得设计侧确认后才可动，且需同步更新本文档。

## 1. 信息架构类

- **不改变首页信息层级**：Hero（问候语 + 当日焦点）是唯一一级焦点；「今日行动中心」是右栏核心；项目横幅、插件 CTA（secondary）、生活区排布已定稿。禁止提升/降低任何区块层级，禁止把首页改成仪表盘式等权网格。
- **不增加无意义页面**：页面清单以 ui-overview.md §3 为准；不为"某个功能像个页面"就开新路由（模型管理曾因此被要求收敛——它不在导航，入口只有设置与 AI 页两个）。空态页、占位页、欢迎页一律不加。
- **不破坏工作台定位**：这是个人工作台，不是后台管理系统。禁止引入：表格化 CRUD 列表页、密集表单页、面包屑导航、树形菜单、多 tab 后台布局、运营后台配色。

## 2. 动效与 Motion Token

- **不新增大型动画**：页面级改动 0 新 token / 0 新动画是历次交付的基线；确需动效只能复用既有 Motion Token 与组件动画（fadeIn / dockIn 等）。
- **Motion Token 双维度不可破**：Duration 与 Intensity 相互独立，**禁止相乘派生**；降级三档（完整/减弱/关闭）只能走 CSS 变量覆盖，**禁止 `!important` 归零**（skin-system.md §9.1 降级块是唯一既有 `!important` 例外）。
- **拖拽绝不能带过渡**：窗口拖动、侧栏折叠手柄、调整大小全程 1:1 跟手；吸附/惯性滑行只在松手后按既定算法执行。
- View Transitions 尚未引入（S2 门限已补齐）；引入前必须先确认哪些局部更新本不该有过渡，方案先审后做。

## 3. 更新机制（S2 纪律）

- **禁止整页重绘替代局部更新**：页面内状态变化只重写目标叶子容器，判据是 DOM 节点身份；既有 `refresh*` 函数索引见 ui-interaction.md §6，新增状态变化优先扩展它们而不是另写 render。
- 禁止把已有真 diff 的页面（设置 / 插件 / 模型 / 档案 / run 状态栏）退回 render()。

## 4. 冻结区（不得触碰）

- **Skin Runtime 与 Motion 系统已冻结**：页面级改动不得修改其内核；皮肤只能按 skin-system.md 的接口扩展。
- 状态机阈值不可随手调：RS_GATE 四态 + 滞回 100、CW_GATE=[1080,880,690,570]、fresh 窗口 700ms、dwell 560ms、Toast 2200ms/最多 2 条——这些数字都经过实测校准（详见 ui-responsive.md / ui-interaction.md），调整必须给出实测依据。
- 组件区排序必须绑 `.wscroll` 真实滚动父容器（历史坑，绑错会静默失效）。
- Esc 优先级链（弹层 > 编辑卡 > 其他）不可重排。

## 5. 技术形态

- **保持单文件原型形态**（内联 CSS + 单 `<script>`），不拆包、不引框架、不加构建步骤——除非用户明确要求工程化。
- 数据全部是 `state` 内存 mock：新增功能用自己的 state 命名空间（`state.xxx`），不污染全局；Runtime 接入只替换数据读写点，不改编译好的 UI 骨架与刷新路径。
- Provider/技术词不泄漏到用户可见文案：用户只能看到 OpenAI / 本地模型 / 个人 Agent 这类展示名（`providerLabel()`），registry / canonical / adapter 等词禁止出现在 UI 文本中。
- 每批改动后必须重跑语法门禁 + 相关 e2e（`check_syntax.cjs` + verify_*.py 套件）；验证在最终产物上跑，"改了源码"不等于"改了被测物"。
