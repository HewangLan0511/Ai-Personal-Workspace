# 响应式规则 · Personal Workspace

> 交接文档 5/6。**只做 PC 端（桌面 + 鼠标）**，不做触摸/平板适配。所有宽度行为由两套机制共同决定：窗口四态状态机（chrome 侧栏）+ 内容档位（页面内容）。

## 1. 双层机制总览

```
窗口宽度 ──► shell[data-rs] 四态状态机（决定侧栏 chrome：导航 / AI dock / 组件区）
         └─► shell[data-cw] 内容档位（决定页面内容布局：堆叠 / 让路）
```

- 两套阈值独立：chrome 占用变化不直接压内容档位（有 700ms fresh 窗口解耦，见 §4）。
- 手动拖宽侧栏与状态机兼容：rs 切换后导航/AI 宽度取 `min(用户设定, 该态上限)`。

## 2. 窗口四态状态机 `shell[data-rs]`（RS_GATE，带滞回）

| 态 | 进入条件 | 恢复条件 | 行为 |
|---|---|---|---|
| **full** | ≥1500 | — | 完整布局：导航 ~220、AI dock 360、组件区 260 |
| **compact** | <1400 | 恢复 +100 | 导航压到 min(用户,180) **文字保留**；AI dock min(用户,260)；组件区让路隐藏 |
| **collapsed** | <950 | 恢复 +100 | AI dock 收成 48px 竖条入口（**无视 force-open**）；导航 `.mini` 图标态 |
| **fallback** | <650 | 恢复 +100 | 兜底单列：所有侧区收起，内容单列 |

- **滞回必须保留**：进入与恢复阈值差 100px，防止临界宽度抖动。
- 旧的 1100px 媒体查询侧栏规则已删除，**chrome 行为只归状态机管**。

## 3. 内容档位 `shell[data-cw]`（CW_GATE = [1080, 880, 690, 570]）

按 `.view` 实际内容宽（ResizeObserver）分档：

| 档 | 内容宽 ≤ | 首页行为（其他页同理：堆叠不删除） |
|---|---|---|
| **lg** | 1080 | 完整双栏 |
| **md** | 880 | Hero 纵排；行动中心移到下方；**内容零删除** |
| **sm** | 690 | 组件区让路（若未在 compact 已隐藏） |
| **xs** | 570 | 极限：自动折导航（`state.cwMini` → `shell.mini`，拉宽即恢复；navMini 优先） |

- 关键校准：1366 窗口在 compact 态实测内容宽 894（比理论少 32px 结构占用），所以 CW_GATE 首档定 1080 而非 1120。
- 首页 grid 已从 inline 样式改为类（`.grid-recent` / `.ws-home` / `.home-split`）——**档位 CSS 依赖类选择器，禁止改回 inline grid**。
- 首页 minmax 护栏：Hero 文字列、行动中心列最小 272px，防止文字被压竖排。

## 4. fresh 窗口（700ms 免上移滞回）

- rs 态切换后 700ms 内内容档位不做"上移"重算：否则旧 chrome 宽度卡住档位、来回横跳。
- 拖拽中（`body.is-resizing`）不触发折导航，防止与拖拽打架。

## 5. 各区域在不同宽度下的预期行为（"这是特性不是 bug"清单）

| 区域 | full | compact | collapsed | fallback |
|---|---|---|---|---|
| 导航 Sidebar | 220 完整 | ≤180 文字保留 | 图标 mini | 收起 |
| AI Dock | 360 展开 | ≤260 | 48 竖条（force-open 失效） | 48 竖条 |
| 组件区 Widget Col | 260 | 隐藏 | 隐藏 | 隐藏 |
| 首页 | 双栏 + 组件区 | 双栏无组件区 | 堆叠 | 单列 |

- 更早的固定断点（widget<1300 / ai<1180 / nav<1100 隐藏侧区）为窗口媒体查询，与 cw 档位互补保留。

## 6. 红线：内容完整优先

1. **任何宽度下不得出现标题竖排、模块互相挤压**。收紧策略永远是"堆叠 / 让路"，不是"删除内容 / 缩字 / 截断"。
2. 工作模式（cinema）下导航自动收窄为图标态是正常行为；AI 折叠态手柄必须保留（它是展开入口）。
3. 禁止为响应式新增大型动画；档位切换无过渡或仅复用既有 token。
4. 禁止在窄宽度下引入移动端交互模式（汉堡菜单、手势等）。

## 7. 验证方式

- `verify_ui04c.py`：CDP 设备模拟逐档验证（内容档位）。
- `verify_ui04cp0.py`：尺寸矩阵 + 滞回动态验证（四态状态机）。
- 改任何阈值 / 档位逻辑后必须重跑这两套 + `verify_collapse_expand.py`（7 条）。
