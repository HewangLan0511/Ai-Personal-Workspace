## 二、防抖机制（两层滞回）

1. **状态机滞回**：full⇄compact 1400/1500、compact⇄collapsed 950/1050、collapsed⇄fallback 650/750。
   动态测试实测：1370 进 compact 后，1470（滞回带内）**保持 compact 不跳回**，1530 才回 full；
   700↔1520 快速扫频十次，终态正确、无异常、零溢出。
2. **内容档滞回**：data-cw 五档（''/lg≤1080/md≤880/sm≤690/xs≤570，按 gutter 与结构占位实测校准）
   上移需 +50px。rs 切换后 700ms 内（chrome 宽度过渡动画期间）免上移滞回——否则档位会被
   旧 chrome 的过渡宽度卡住（实测坑：1366 compact 内容 894 被 +50 卡在 md，Hero 误堆叠）。
3. **拖拽防打架**：用户拖侧区宽度中（body.is-resizing）不做自动折叠。

## 三、首页保护机制

1. **minmax 承载护栏**：`.hero` 文字列 `minmax(0,1fr)`、`.home-split` 右列（今日行动中心）
   `minmax(272px,1fr)`、左列 `minmax(0,…)`——列宽有底线，压不进就换档，不硬挤。
2. **内容零删除**：所有状态切换只动布局不动 DOM；兜底档五区块（问候/CTA/最近使用/行动中心/工作空间卡）
   e2e 逐项点名在场。
3. **禁竖排护栏**：导航文字在 COMPACT 保留（只收宽度不藏文字）；问候/标题列全部 minmax(0,·)
   + 堆叠换档，1366/1100/900/600 实测 navVert=false。

## 四、滚动体验检查（登记结论）

- **结构检查**：首页只有一个滚动层（.view），问候区/Hero/区块均为普通文档流，无嵌套滚动容器、
  无视区内固定头造成割裂 —— 结构层面无问题，未做改动。
- 保留 UI-04-C 已落地的三项：`scrollbar-gutter: stable`（跨路由不跳宽）、全滚动区
  `overscroll-behavior: contain`（不串层）、内层滚动区统一 8px 细滚动条。
- **轻量滚动反馈：未添加**。需要滚动监听 + 视觉效果，与"不新增无必要动画/复杂监听"冲突；
  现有 smooth scroll + 稳定 gutter 已覆盖"视觉移动感"的主要抱怨源。如验收后仍觉得不足，
  建议下一批单独立项（滚动进度条或顶栏投影，二选一，都是 30 行内的活）。

## 五、实现与纪律

- **单一 ResizeObserver**（rAF 节流）驱动两层：窗口状态机（rsStateOf，纯函数递归 + 滞回）
  与内容档（cwTierOf，滞回 + fresh 窗口）。状态切换只写 `shell.dataset.rs` / `dataset.cw` /
  `.mini` class，**零 render()、零布局重算循环** —— S2 纪律保持。
- CSS 只增不改：10d 状态机 chrome 策略 + 10b minmax 护栏；旧窗口媒体查询中与状态机冲突的
  侧栏规则（1100 藏文字）已删除（chrome 归状态机管）。0 新 token、0 新动画。
- 首页 inline grid 样式已类化（UI-04-C 完成，本批沿用）。

- 滞回带数值（100px/100px/100px 与内容档 +50px）为桌面合理经验值，可在 `RS_GATE`/`CW_GATE`
