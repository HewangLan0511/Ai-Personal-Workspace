# UI-04-C 验收报告 · 首页响应式系统 + 全局滚动体验（2026-09-15）

约束达成：不改变信息架构、不删内容、优先保持首页完整性、达到极限后折叠侧边导航。
执行后停留验收。

## 一、根因诊断（为什么"换设备尺寸后首页挤兑、标题竖排"）

原响应式全部基于**窗口宽度**媒体查询（1300/1240/1180/1100/960/820/680）。但首页实际可用
宽度 = 窗口 − 导航(160~400) − 组件区(0~400) − AI 栏(48~560)，且三侧栏都能**手动拖宽**。

典型事故：窗口 1600 + AI 栏展开 360 + 组件区 224 → 内容区只剩 ~780px，此时所有窗口断点
都"未触发"，Hero 仍按 `1fr 200px` 双列硬撑、今日行动中心仍挤在 1fr 窄列 → 挤兑、标题竖排。
**窗口断点感知不到侧栏的真实占用，是根因。**

## 二、方案：内容区宽度驱动（ResizeObserver 分档）

JS 在 `.view` 上挂 ResizeObserver（rAF 节流），按**内容区实际宽度**写 `shell[data-cw]`：

| 档位 | 内容区宽度 | 动作（先收紧 → 再堆叠 → 最后折叠导航） |
|---|---|---|
| （无） | >1120 | 完整布局：Hero 双列 200px map、双栏 2fr/1fr、最近使用 6 列 |
| lg | ≤1120 | Hero map 收 160、双栏收 1.6fr/1fr（不删任何东西） |
| md | ≤920 | **Hero 纵向堆叠（map 暂藏）**、行动中心移到工作空间下方、最近使用 3 列、问候区提示语隐藏 |
| sm | ≤720 | 组件区让路收起、工作空间卡 2 列、AI 栏收竖条（尊重 force-open）、页边距收紧 |
| xs | ≤600 | **极限档：侧边导航自动折叠**（state.cwMini → shell.mini 64px）；最近使用 2 列、工作空间卡 1 列 |

关键设计决策：
1. **内容零删除**：md 档堆叠只是"换位置"——今日行动中心整体移到工作空间下方，区块/按钮/文本全部保留
   （T2/T4 e2e 逐项点名验证）。Hero map 是装饰性小地图，仅在堆叠档暂藏。
2. **极限才折导航**：xs 档触发 `state.cwMini`，复用既有 shell.mini 折叠机制（64px 图标栏）；
   窗口拉宽**自动恢复**；用户手动折叠/展开（navMini）永远优先于自动档。
3. **拖拽防打架**：边界拖拽进行中（body.is-resizing）不做自动折叠判定，拖完由 RO 自然收敛——
   避免用户把导航拖宽时被系统抢折叠。
4. **live 升档**：收起 AI 栏 / 组件区，内容区变宽，档位即时回升——不需要动窗口。
5. 首页 inline `grid-template-columns` 改为类（.grid-recent/.ws-home/.home-split），
   否则档位 CSS 打不过 inline 样式（这是原方案即使加断点也会失效的暗坑）。

## 三、全局滚动体验

1. `.view` 加 `scrollbar-gutter: stable`：路由切换跨过溢出边界时内容不再左右跳。
2. 全部滚动区（.view/抽屉体/AI 消息/会话列表/组件区/弹窗）加 `overscroll-behavior: contain`：
   滚到头不再把滚动串给外层/页面。
3. 内层滚动区统一细滚动条（8px，hover 加深）：原来只有 .view 定制过，抽屉/AI 消息是系统默认粗条。

## 四、新增/删除组件

- 新增：`initCW()`（ResizeObserver + 档位计算）、`shell[data-cw]` 档位 CSS（10b 节）、
  滚动体验 CSS（10c 节）、`.grid-recent/.ws-home/.home-split` 类、`state.cwMini`。
- 删除：首页三处 inline grid 样式（等价迁移为类）。0 新 token、0 新动画
  （min-width:0 与 flex-wrap 是防挤压修正，非动效）。

## 六、边界说明
- 档位阈值（1120/920/720/600）按现有密度取值，后续可按真实设备数据微调，只动 tierOf 一个函数。
- 窗口宽度媒体查询（原 10 节）保留未删：它们继续负责与内容区无关的固定行为
  （组件区 <1300 隐藏、AI <1180 收竖条、<820 工作台纵向等），与 cw 档位互补不冲突。
