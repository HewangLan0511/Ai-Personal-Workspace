承接 UI-05-P0 吸附系统，升级为「落位 + 剩余空间自动填充 + 窗口间交换/插入」。

## 一、修改说明

### 吸附分区三类（28px 进入范围，全程只出预览、绝不干预拖动）
1. **edge 舞台边缘**（既有增强）：左缘→左半区、右缘→右半区、顶部→最大化。
   **松手后剩余空间自动填充**：本窗落位半区，其余窗口竖排均分填满另一半（`fillRemaining`）。
   顶部最大化无剩余空间 → 他窗原位保留（在底层，属该操作的自然结果）。
2. **swap 交换**：拖动窗 **>55% 覆盖**别的窗 → 该窗上出「交换位置」实线预览 → 松手两窗几何互换。
   阈值 55% 是刻意的：轻微重叠不算交换，**用户主动拖出的部分重叠原样保留**（验收 3）。
3. **insert 插入**：拖动窗贴近别的窗左/右缘（垂直同带）→ 「插入分屏」预览（占其半）→
   松手两窗各占该窗一半，**其余窗口一律不动**（验收 2）。

优先级：舞台边缘 > 交换 > 插入。预览层区分：edge=虚线框；swap/insert=实线框+中央文字提示
（「交换位置」/「插入分屏」），纯 CSS content，无 JS 文案节点。

### 明确不做（按验收要求）
- 拖动过程**永不**自动移动其他窗口、永不吸引窗口本身（e2e 中途采样实证他窗零牵动）；
- 无飞行动画/transform 缩放；落位反馈复用既有 flash(just-swap)。

## 二、数据结构

- `snapZone = {type:'edge'|'swap'|'insert', zone, target?, otherPart?}`（拖拽期临时态，不持久化）。
- customLayout 不变（{ws, mode, rects}）——"窗口关系"以**几何+模式**表达：吸附/交换/插入的结果
  都是确定几何，保存后逐字恢复（验收 5 实证逐项一致）。

## 四、未完成风险

1. 交换阈值 55% 为经验值，可在 `updateSnap` 的 `cov > 0.55` 一处调整。
2. edge 落位的填充是"竖排均分"，未考虑他窗原有大小权重（tileRects 才有权重）——如需
   "按原面积比例分配另一半"，是 10 行内的后续增强。
3. 顶部最大化后他窗被盖住，Windows 会弹 Snap Assist 选择栏——原型阶段从简未做。
